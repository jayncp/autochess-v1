# 阵容码：计划

把一方的阵容写成一段可以复制、粘贴、手改的文字，用来导出和导入。先在科研模式里用，以后对战、冒险、阵容保存都用同一套。

```
鹦鹉+狮心 / 士兵 / 士兵 / 千机魔女+铁剑
```

只有文字这一种形式。导入时只和当前版本的卡核对：认得出的位置导入，认不出的位置空着并说明，玩家调整后再导出就是新的。
不做压缩码、永久编号、曾用名、数据版本号（讨论过，见第 6 节）。

第 3 节的用例是用来核对设计的，实现时原样变成测试。

## 1. 写法

一个阵容码是**一方**的阵容：从交战位往后最多 7 个位置，每个位置是一个角色加可选的一件装备。

**导出**只有一种写法：

- 位置之间是 ` / `（两边各一个空格）；
- 有装备的写 `角色+装备`，中间没有空格；
- 卡名用当前语言的名字；
- 空着的卡位跳过不写（开战时本来就自动往前补）。

**导入**放宽，因为文字会经过聊天软件、输入法和手改：

- 分隔符两边的空格、制表符忽略；换行也当作位置分隔（可以一行写一个位置）。
- 全角的 `＋` `／` 当成半角。
- 卡名要完全匹配，认现在的卡名和英文 id；不做模糊匹配。
- 卡名内部的空格不动（中文名没有空格，以后英文名会有）。

卡名里不能有 `+`、`/` 和它们的全角写法，卡名之间不能重复（测试保证）。现在 144 张卡都满足。

搜索报告里的阵容就是这个写法（`牛头人+天使翅膀 / 光灵 / 沼泽之王+噬心药剂`），可以直接贴进游戏。

## 2. 导入的规则

按位置一个一个看，互不影响：

- 第 k 段文字对应第 k 个卡位。
- 角色认得出：放上去。装备认得出就带上，认不出就不带装备。
- 角色认不出（写错了、卡已经删了或改名了、写的是一件装备）：这个卡位空着。
- 一段是空的（`老虎 / / 士兵`）：这个卡位空着，不算问题。
- 超过 7 段：只取前 7 段。
- 一个角色都认不出：不导入，原来的阵容不动。

有问题的地方汇总成一条说明，写清是第几个位置、哪个名字。

## 3. 用例

### 导出再导入

| # | 阵容 | 文字 |
|---|---|---|
| 1 | 只有一个角色 | `老虎` |
| 2 | 带装备、有重复 | `鹦鹉+狮心 / 士兵 / 士兵 / 千机魔女+铁剑` |
| 3 | 7 个位置 | `密林射手 / 萨满 / 幻梦菇+八咫镜 / 骑士王+锁子黄金甲 / 海德拉 / 齐天大圣+如意金箍棒 / 六翼天使+千机之匣` |
| 4 | 卡位 1、3 有角色，卡位 2 空着 | 导出是 `老虎 / 士兵`；再导入时在卡位 1、2 |

用例 1–3 导入后再导出，还是同一段文字。全部 144 张卡各写一次再读回来，结果不变。

### 宽松的读法（都读成用例 2）

| # | 输入 | 说明 |
|---|---|---|
| 5 | `鹦鹉+狮心/士兵/士兵/千机魔女+铁剑` | 没有空格 |
| 6 | `鹦鹉 ＋ 狮心 ／ 士兵 ／ 士兵 ／ 千机魔女 ＋ 铁剑` | 全角符号，多余的空格 |
| 7 | 一行一个位置（四行） | 换行分隔 |
| 8 | `parrot+lionheart / soldier / soldier / clockwork_witch+iron_sword` | 英文 id |
| 9 | `  鹦鹉+狮心 / 士兵 / 士兵 / 千机魔女+铁剑  ` 加首尾空行 | 首尾的空白 |

### 部分导入

| # | 输入 | 卡位 1–3 | 说明里写 |
|---|---|---|---|
| 10 | `鹦鹉+狮心 / 士宾 / 士兵` | 鹦鹉+狮心、空、士兵 | 第 2 位：不认识"士宾" |
| 11 | `鹦鹉+师心 / 士兵` | 鹦鹉（不带装备）、士兵 | 第 1 位：不认识装备"师心" |
| 12 | `鹦鹉+士兵 / 士兵` | 鹦鹉（不带装备）、士兵 | 第 1 位："士兵"不是装备 |
| 13 | `狮心 / 士兵` | 空、士兵 | 第 1 位："狮心"不是角色 |
| 14 | `+狮心 / 士兵` | 空、士兵 | 第 1 位：没有角色 |
| 15 | `鹦鹉+狮心+铁剑 / 士兵` | 鹦鹉+狮心、士兵 | 第 1 位：只能带一件装备 |
| 16 | `老虎 / / 士兵` | 老虎、空、士兵 | 没有问题，不弹说明 |
| 17 | 9 个位置 | 前 7 个 | 最多 7 个位置，后 2 个没有导入 |

### 不导入

| # | 输入 | 提示 |
|---|---|---|
| 18 | 空白 | 没有可以导入的角色 |
| 19 | `你好`、`士宾 / 师心` | 没有可以导入的角色（并列出不认识的名字） |

### 加人、改人之后

| # | 发生了什么 | 以前导出的文字 |
|---|---|---|
| 20 | 加了新卡、新种族、模组的卡 | 都不变；新卡直接用名字 |
| 21 | 调了数值或技能 | 照常导入，按现在的数值算 |
| 22 | 一张卡改了名，或者删掉了 | 那个位置空着，说明里写不认识哪个名字；玩家补上后再导出就是新名字 |
| 23 | 图鉴里换了顺序、英文 id 改了 | 中文的文字不受影响 |
| 24 | 换了游戏语言 | 用英文 id 写的照常导入；用另一种语言的卡名写的，认不出的位置空着 |

## 4. 界面（只做科研模式）

右列"清空全部"下面加一个"阵容码"按钮，双方共用一个面板：

```
┌─ 阵容码 ─────────────────────────┐
│ ( 对方 ) ( 我方 )                 │
│ ┌──────────────────────────────┐ │
│ │ 鹦鹉+狮心 / 士兵 / 士兵 /      │ │
│ │ 千机魔女+铁剑                  │ │
│ └──────────────────────────────┘ │
│        [ 复制 ]  [ 粘贴 ]  [ 导入 ] │
└──────────────────────────────────┘
```

- 只有一个文本框：打开时里面是这一方现在的阵容，可以直接复制；也可以在里面改或者贴上别的，再点"导入"。
- 打开时是当前选中的卡位所在的一方；对方、我方用旗帜的红、蓝区分。切换一方时文本框换成那一方的阵容。
- "复制"复制文本框里的内容，成功后按钮上的字变成"已复制"一下。"粘贴"把剪贴板的内容放进文本框（有的手机和网页版读不到剪贴板，这时用系统自带的粘贴）。
- "导入"：这一方已有角色时先确认"将替换我方当前的阵容"。导入后文本框换成导入后的阵容（标准写法）；有要说明的就在文本框下面列出来，没有就关掉面板。
- 这一方没有角色时文本框是空的，带一句提示"在这里粘贴或输入阵容，如：老虎+狮心 / 士兵"。

面板是共用组件（和对话框、筛选项放在一起），带一个"能不能导入"的开关。这次只在科研模式挂；关卡布阵页以后只开导出。

## 5. 代码和测试

- `scripts/core/lineup_code.gd`（`LineupCode`）：纯逻辑，不依赖场景。`write(阵容)` 得到文字；`read(文字)` 得到 7 个卡位和问题的列表。阵容的格式和 `BattleSim` 一样是 `[[角色 id, 装备 id], ...]`，空卡位是 `[]`。
- `scenes/components/ui/lineup_code_panel.gd`：面板。
- 翻译：按钮、提示和各种问题的说明都走 `ui.csv`。
- 测试：
  - 用例文件 `tests/cases/lineup_codes.json`，第 3 节的用例；
  - 数据检查加两条：卡名互不重复、卡名里没有分隔符；
  - 全部卡写一次再读回来；
  - 冒烟流程：科研模式里打开面板，复制我方，清空，再导入，阵容和原来一样；导入到已有阵容的一方会先确认；导入带问题的文字会列出说明，认不出的卡位空着。
- 文档：规范写成 `docs/design/lineup-code.md`（活文档，从第 1、2 节整理）；`AGENTS.md` 的"新增卡牌"里加一句卡名不能含分隔符；路线图、进度同步。

一个 PR。验收：`just test` 通过，第 3 节的用例全部通过，按下面的例子手动过一遍。

手动验收（科研模式）：

1. 我方摆"鹦鹉+狮心、士兵、士兵、千机魔女+铁剑"，打开阵容码：文本框里是用例 2 的文字。
2. 复制，切到对方，粘贴、导入：对方出现同样的阵容。
3. 把文本框改成 `老虎/士宾/士兵`，导入到我方：先问是否替换；确认后我方卡位 1 是老虎、卡位 2 空着、卡位 3 是士兵，下面写着"第 2 位：不认识'士宾'"。
4. 文本框里只写 `你好` 再导入：提示没有可以导入的角色，阵容不变。
5. 从搜索报告里复制一套阵容贴进来，能导入。
6. 手机宽度、紧凑模式下面板不超出屏幕。

## 6. 讨论过、这次不做的

- **压缩码**：把文字通用压缩后反而更长（25 个字变成 64 个字符）；按卡编号的压缩码要维护一张永久编号的表，模组之间还会抢号。文字本身已经够短，以后真有需要再加，可以用"由英文 id 算出短代号"的办法，不需要建表。
- **永久编号、曾用名**：为了让旧码在改名后还能认。现在改名的卡按认不出处理，玩家补上再导出即可。
- **数据版本号**：为了提示"数值可能已变"。阵容码只说是哪些卡，不保证强度，不带版本。
- **一个码包含双方**：两边各复制一次就够。
