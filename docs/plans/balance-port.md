# 数值校正的结果写进正式版：计划

把 [`balance-tuning.md`](balance-tuning.md) 定下的候选数值和新机制，从"只在 Rust 版里的试验"变成正式规则和正式数据。
候选数值在 `docs/design/balance-trial.xlsx`，和正式数据不同的 119 张卡在 `tools/balance/trial.json`。

这份计划先解决一个问题：**新机制和现有的结算框架是否兼容，哪些要动框架、哪些只是加一个效果**。结论在第 2 节，拍板的事在第 5 节。

## 1. 范围

- 5 种新效果、2 个多一轮的范围、2 个新对象，在 GDScript 版实现。
- 6 个试验开关：逐个变成正式规则（第 3 节），Rust 版的开关删掉。
- `data/cards.json` 更新 119 张卡；5 件装备改名、改 id；精灵公主和星辰法师互换星级后重排编号。
- 卡面文字、翻译、显示顺序、回放表现。
- 跟着失效的东西重做：两个关卡、冒烟用例、有效战力。
- 文档同步。

不做：新卡、卡图、进一步调数值。数值在这一步里一个都不改，保证做完后用 `just balance run` 重跑的结果和收尾版（g1）一致，这是整件事的验收标准。

## 2. 和现有框架是否兼容

现有框架（`battle-rules.md` 第 4 节，`BattleSim`）的三个支点：

- 一个时点从上到下走七步（记 → 增 → 删 → 改 → 加 → 减 → 醒），再结算基础技能；带时机的特殊技能各属于一步（`STEPS`）。
- 被动不占步骤，挂在"己方角色触发 / 结算了某个技能"这件事上（`_on_trigger`、`_after_resolve`、`_hit`），或者在取多一次、多一轮时查（`_extra_resolves`、`_extra_rounds`）。
- 伤害统一走 `damage()`：庇护 → 坚固 → 扣战斗力。

逐条对照：

| 新东西 | 放在哪 | 要不要动框架 |
|---|---|---|
| `on_trigger_boost`（队长、头狼） | `_on_trigger`，和 `on_trigger_gain` 并排，区别只是加给谁 | 不用 |
| `gain_all_if_outnumbered`（神裁者） | "记" + "加"，和 `gain_if_outnumbered` 共用记录 | 不用 |
| `next_two`（彼岸花妖） | `targets()` 多一个分支 | 不用 |
| `self_and_second`（精灵女皇） | `_extra_rounds` 多一个分支，用开战时的序号 | 不用 |
| `self_and_front`（虎尾神鞭、圣杯） | `_extra_rounds` 多一个分支 | **第一个按当时队列算的范围**，见 2.1 |
| 对象 `self`（牛头人、白狼王） | `targets()` 多一个分支，用已有的 `grant`（"增"） | 不用，见 2.2 |
| `execute`（眼镜王蛇、淬毒匕首） | "记" + "减"，走 `damage()` | **伤害流程里要认"致命伤害"**，见 2.3 |
| `halve_pre_battle_damage`（雪域神牛） | `damage()` 里 | **伤害流程多一步，而且要知道当前是哪个时点**，见 2.4 |
| `on_enemy_trigger_gain_all`（八咫镜） | 对方结算技能时 | **第一个听对方事件的被动**，见 2.5 |

也就是说，9 样里 5 样只是照着已有的效果再加一个，4 样碰到了框架原来没有的概念。这 4 样都能放进现有结构，不需要重排步骤，但每一样都要在规则文档里补一条口径。

### 2.1 "前一位"是动态的

现有的范围只有三种：自身、己方全体、开战时位于第 1 位（固定，用开战时的序号）。"自身和前一位"是按当时的队列算：前面的角色阵亡后，换成新的前一位；持有者自己到了交战位就没有前一位。

- 多一轮是在每个时点开始时现查的，所以动态范围本身没有问题。
- 要写进规则的口径：入场时点只有交战位在执行入场，所以圣杯的"前一位入场多触发一轮"只在持有者排第 2 位、前一位正在入场时生效。这一点卡面上看不出来，要在规则里写明，图鉴的说明里也要提。
- 和"下一位"对称：`next_unit` 已有，加一个 `prev_unit`。

### 2.2 牛头人和白狼王用"获得"

试验里最初给这两张做了一个单独的效果（"改"自身的某个数值），牛头人的"坚固值 +1"会让"改"第一次作用于词条，还要另定"自己没有这个词条时怎么办"。已经改成用已有的"获得"（`grant`），对象加一个"自身"：

- 牛头人："坚固4；交战：自身获得坚固1"。
- 白狼王："交战：自身获得狂暴3"。

"获得"的口径已经有了（没有的加上，已有的数值相加），军团圣盾就是给己方全体坚固2。

- 坚固不会被别的效果减少或清除（清除只针对基础技能，现在也没有减技能值的效果）；步骤固定是 增 → 删 → 改，不会出现先减到 0 再加的情况。
- 白狼王的狂暴被清除（美杜莎女王、石化之眼）之后，下一次交战会重新获得 3。
- 白狼王带千机之匣时，获得的是狂暴6（获得的基础技能数值翻倍，现有规则）。

### 2.3 致命伤害

致命现在只在对撞里：攻击值按 10000 算，对方免疫致命时按普通对撞算。`execute` 是在特殊技能的"减"那一步打一下致命伤害，没有"普通伤害"可以退回。

- 口径（已定）：庇护能挡，消耗一层；对免疫致命的角色是 0 点；坚固不减。
- 做法：`damage()` 的调用方先判断免疫致命，免疫就不调用（不消耗庇护、不出伤害事件，只弹"免疫致命"）。
- 细节（按试验里的实现）：
  - 比较战斗力是在"记"那一步，这时双方本轮的入场技能都还没结算。双方都带时各按记录算，可能同时把对方打掉。
  - 多一轮（骑士王）时每一轮重新比较、重新打，和沼泽之王一致。
  - 事件里的 `source` 加一个取值（如 `execute`），回放按致命的样式表现。

### 2.4 伤害减半

这是伤害流程（第 5 节）第一次加步骤，也是 `damage()` 第一次需要知道"现在是哪个时点"。

- 顺序（已定）：庇护 → 坚固 → 减半，四舍五入（0.5 远离零，1 点还是 1 点）。
- 做法：`BattleSim` 记下当前时点（进 `resolve_timing` 时设、出来时清），`damage()` 在坚固之后看目标有没有这个词条。
- 范围：战前时点里的所有伤害，不管来源（腐蚀、湮灭、特殊技能造成的）。战前没有对撞、协战、反噬，所以不用考虑它们。
- 事件：`damage` 效果加一个字段（如 `halved`），`dealt` 是减半之后的数。回放弹词条名。
- 做成描述型效果（已定），卡面写原句"战前受到的伤害减半"，不另起词条名。

### 2.5 听对方事件的被动

现有的被动都是"己方角色触发 / 结算……时"。八咫镜是"对方角色结算基础技能时，己方全体战斗力 +1"。

- 放在哪：和 `on_resolve_bonus`、`on_resolve_raise` 同一个位置（每一下结算之后），只是查的是对方的持有者。`_holders` 本来就是按方记的，取对方的那一份即可。
- 同一拍里双方同时结算，这条被动加的是战斗力，和先后无关，不破坏"同一拍互不影响"。
- **真正的问题在回放**：对方每结算一下，己方全体各弹一次 +1。后期一个时点里对方能结算十几下，己方 7 个角色，就是上百个飘字。
  - 事件日志照实记（每一下一组效果），保证和 Rust 版逐场一致。
  - 回放（已定）：一拍里合并成一次，弹一次"八咫镜"，己方全体同时出一次加战斗力的特效，数字是这一拍里加的总数（对方这一拍结算了 3 下就是 +3）。只改回放，不改结算。
  - 做完后用 `just replay-time` 看带八咫镜的对局时长有没有明显变长。

## 3. 六个开关怎么转正

全局开关只适合试验。转正时每一条都要落到具体的效果 id 或参数上，否则同一个 id 在不同卡上口径不同，卡面文字也对不上。

| 开关 | 现在的做法 | 建议转正成 |
|---|---|---|
| 萨满按轮算 | `on_resolve_raise` 被开关改成一轮加一次 | 只有萨满用，直接改名 `on_trigger_raise`、改口径（3.1） |
| 星辰法师按每一下算 | `on_trigger_gain` 技能写 any 时被开关改成按结算算 | 新 id `on_resolve_gain`（"己方角色结算基础技能时……"）。"触发"按轮、"结算"按下，和 4.4 的用词一致；`on_trigger_gain` 留给沼泽触手，不再支持"任意基础技能" |
| 炼药师加全部 | `gain_half_skill_sum` 被开关改成不除以 2 | 改名 `gain_skill_sum`，口径直接改；没有别的卡用"一半" |
| 千机魔女三倍 | `double_equipment` 被开关改成 ×3 | 改名 `equipment_times`，写数值（3） |
| 千机之匣战斗力也翻倍 | `double_skills` 被开关改成开战时战斗力 ×2 | 口径直接改：在装备合并时把宿主的战斗力翻倍，见下 |
| 鹦鹉额外获得 | `copy_skills` 被开关从"变成"改成"相加" | 口径直接改，事件 `copy` 的含义从"变成"改成"获得"；鹦鹉、鹦鹉手偶的时机改成战前、入场两个 |

千机之匣（已定）：

- 千机之匣自己没有战斗力，翻倍的就是宿主的战斗力，在装备合并时翻倍，和基础技能数值一样，卡面显示翻倍后的数（规则第 3 节"卡面上显示的就是翻倍后的数"不用改）。
- 战斗中获得的战斗力不翻倍；战斗中获得、被加的基础技能数值照旧翻倍。
- 千机之匣和千机魔女的效果都是特殊技能，只有一格，魔女带上千机之匣就没有自己的效果，不存在叠加顺序。

### 3.1 "触发后"在什么时候加（已定）

萨满："己方角色触发腐蚀后，己方全体的腐蚀值 +1"。一个角色在一轮里把腐蚀结算完（含多结算的那几次）之后加一次；连续几次结算之间数值不变。同一拍里排在后面的角色用的是加过的数；多一轮、被唤醒的一组各算一次触发。

例：两个腐蚀5 的角色，己方腐蚀多结算一次，带萨满。第一个 5、5，加到 6；第二个 6、6，加到 7。

Rust 版的试验实现已经改成这个口径并重跑过（g1，见 `balance-tuning.md` 4.9）：萨满的出场率小降，格局没有变。

"结算时"的被动（星辰法师、八咫镜、蟾蜍）和那一下一起生效；它们加的是战斗力或伤害，不改技能值。

## 4. 分几步做

三个 PR，每个都能单独验证。

### 第 1 步：规则（不动正式数据）

- GDScript 版实现第 2、3 节的全部内容。每种效果先做测试卡（`t_` 开头）和规则用例，再写实现；`just record` 重录并逐条核对。
- `CardDB` 的校验表（`SPECIAL_SKILLS`、`DESCRIPTIVE_SPECIALS`、`SPECIAL_PARAMS`、`SCOPES`、`TARGETS`）和 `tests/cases/card_checks.json` 同步。
- 改了口径的几条（鹦鹉、炼药师、千机魔女、千机之匣、萨满、星辰法师）现有用例跟着改。这几张正式卡的效果是原地改口径或改名，所以规则一改，它们在游戏里的表现就已经是新的，比其余的卡早一个 PR；数据里只动特殊技能的写法（id、参数），不动数值。
- `BattleSim.VERSION` 加一。
- Rust 版对齐：效果改成正式的 id，删掉 `trial.rs` 和"试验"标记；`just rs-test`、`just diff-sim` 零差异。
- `battle-rules.md`：4.3（范围）、4.4（听对方的被动）、第 5 节（减半）、6.2/6.3（新效果的表）、6.4（改词条）、7.1（新对象：该角色、前一位、下两位；致命伤害）、7.2（显示顺序）。`data/README.md` 的参数写法。
- 翻译：`effect.<id>`、`scope.<id>`、`target.<id>`、新词条的说明。
- 回放：新效果能正确播放（不求好看，求不出错）。

验收：`just test` 全过；对拍零差异；`tools/balance/trial.json` 改成新 id 后，`just balance run` 的结果和收尾版一致（这时试验开关已经没有了，全靠正式规则）。

手动验收：这一步正式卡大多还是旧数值，新机制用科研模式看不全，所以给一份清单，每种新机制一个最小的例子（双方阵容、预期的每一步数值、实际的事件日志），外加能在科研模式里直接摆出来看回放的几个：鹦鹉（获得而不是变成）、炼药师、千机魔女 + 装备、千机之匣（卡面战斗力翻倍）、萨满 + 密林射手（两次腐蚀数值相同，之后才加）、星辰法师。

### 第 2 步：数据

- `data/cards.json` 按试验表更新 119 张卡。用脚本从 `tools/balance/trial.json` 生成，再和试验表逐张核对。
- 5 件装备改 id 和名字（对照表在 `balance-tuning.md` 第 7 节）。
- 精灵公主（4★）、星辰法师（3★）重排编号，图鉴顺序跟着变。
- 两个关卡之后会重新设计，这一步不管它们的解还成不成立：只保证能正常进入和开战，`docs/design/levels.md` 和路线图里注明待重做。
- 冒烟用例重新生成（`just levels`、`just gen-random`）。
- `tools/balance/`：`trial.json` 清空，`overrides.json` 删掉，起点阵容里的 id 替换；`tools/README.md` 里相应的说明改掉。
- `card-workbook.xlsx` 的状态改回"已实现"。

验收：`just test` 全过；`just balance run --official`（或清空后的默认）结果和收尾版一致。

手动验收：图鉴里 119 张卡的卡面文字和数值对照试验表（给一份对照清单，标出文字和表里不完全一样的）；科研模式里按清单摆几套有代表性的阵容看回放：眼镜王蛇打高战斗力和打免疫致命的、雪域神牛吃战前腐蚀、八咫镜、圣杯和虎尾神鞭（前一位阵亡前后）、精灵女皇、队长和头狼、神裁者、彼岸花妖；两个关卡能打完不报错。

### 第 3 步：收尾

- 回放表现打磨：八咫镜的合并显示、致命伤害和伤害减半的样式；`just replay-time` 对比前后。
- 有效战力重测（`just experiment effective_strength`），填回设计表，更新 `card-design.md` 的各星级均值。
- `game-design.md` 对照新环境检查；`decisions.md` 记下拍板的事；`AGENTS.md`、`PROCESS.md`、路线图同步。

手动验收：带八咫镜、多一轮、多一次的长对局各看一场回放（给阵容），看飘字是否看得清、节奏是否拖沓；`just replay-time` 的前后对比附在 PR 里。

## 5. 拍板的事

- 六个开关都落成具体的效果（第 3 节）：新增 `on_resolve_gain`，`on_resolve_raise` 改名 `on_trigger_raise`，`gain_half_skill_sum` 改名 `gain_skill_sum`，`double_equipment` 改名 `equipment_times`，其余原地改口径。
- 千机之匣：宿主的战斗力在合并时翻倍，卡面显示翻倍后的数；战斗中获得的战斗力不翻倍，获得的基础技能数值翻倍；和千机魔女的效果不会同时存在。
- 萨满："触发后"是这个角色一轮里的腐蚀全部结算完之后（3.1）。
- 牛头人、白狼王用"获得"（2.2）。
- 雪域神牛：描述型效果，卡面写原句（2.4）；伤害流程是 庇护 → 坚固 → 减半 → 扣战斗力。
- 八咫镜在回放里一拍合并显示一次（2.5）。
- 两个关卡之后重新设计，这次不纳入。
- 一个 issue，三个 PR；每个 PR 附手动验收的例子。
