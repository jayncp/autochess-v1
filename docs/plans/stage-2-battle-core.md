3. **无头命令** `cli/sim.gd`：批量模拟，供测试、关卡工具、平衡实验使用。
4. **补齐规则**：实现湮灭、基础技能整体替换。
5. **工具**：
   - 关卡枚举；
   - Python 平衡实验，先复现旧报告的数据；
   - 圣水补偿校准。

**结果不变**：基线用例的期望值不重录，`just test` 全部通过。

**不在本阶段做**：新卡和三星/四星的复杂机制（阶段 3）、UI 美化。

## 1. 战斗核心 `BattleSim`

### 1.1 接口

- 位置：`scripts/core/battle_sim.gd`，纯 GDScript（`RefCounted`），不碰场景节点。
- 输入：双方阵容 `[[角色 id, 装备 id], ...]`，与基线用例格式相同。
- 输出：
  - 结果：胜负，以及双方幸存单位的战力；
  - 事件日志：见 1.4。
- 单位用"座位-初始序号"标识，如 `1-0` 是 P1 原来的第一个。

### 1.2 流程

- 完全按 [battle-rules.md](../design/battle-rules.md) 第 2 节，也就是现在跳过模式的结算顺序。
- 平局判定的时点和现在一致：
  - 战前每一步、主循环每一轮开头各检查一次；
  - "连续 20 轮无人阵亡"只在主循环里计数。
- 顺带修掉一个问题：现在点"跳过"会额外做一次胜负判定，让"连续 7 次战力不变"的计数多 1，极少数情况下平局会提前一次。改完后结算只在核心里做一遍，不受按键影响。

### 1.3 扩展位置

结算集中在下面 5 处。原三星效果（[part2 报告第 1 节](../design/balance-report-2026-11-01-part2.md#1-原三星效果的实现口径)）都能挂到其中一处：

| 位置 | 作用 | 阶段 3 可能挂上的效果 |
|---|---|---|
| `CardDB.combine` | 角色和装备合并 | 勇者（装备战力 ×2）、勇者之魂 |
| 开战前 | 战前阶段之前执行一次 | 地狱之主（振奋转湮灭）、模仿面具 |
| 时机触发 | 某单位在某时机执行普通技能 | 精灵女王、战神（多触发一次） |
| 单条技能结算 | 狂暴、集结、腐蚀、振奋、湮灭各结算一条 | 大王花（腐蚀 +5）、污染源（腐蚀两次）、猎人（对方狂暴时） |
| 伤害流程 | 坚固 → 庇护 → 扣战力；伤害带来源（交战、腐蚀、湮灭、反噬） | 神圣精灵（免疫腐蚀） |

### 1.4 事件日志

战斗场景靠它播放动画，测试用它做自洽检查，以后的复盘和 AI 也能用。草案：

| 事件 | 内容 | 动画 |
|---|---|---|
| `pre_battle` | 战前第 k 步的双方单位 | 上前 |
| `enter`、`engage` | 交战位触发入场、开始交战 | 上前 |
| `skill` | 某单位按某时机执行普通技能 | 放技能、蓝字（入场、交战） |
| `buff` | 狂暴、集结、振奋：单位、技能、数值、结算后的战力 | 绿字 |
| `damage` | 单位、来源、数值、坚固减免、是否被庇护挡下、结算后的战力 | 红字；坚固、庇护显示绿字 |
| `clash` | 双方的攻击值（致命为 10000） | 对撞 |
| `death` | 阵亡单位 | 淡出，后排补位 |
| `end` | 胜负和原因：一方全灭、连续 7 次不变、连续 20 轮无人阵亡 | 显示结果 |

每个改变战力的事件都带"结算后的战力"，回放时直接显示，不用自己再算一遍。

### 1.5 补齐的规则

- **湮灭N**：
  - 在普通技能的最后结算；
  - 对方队列从前到后，每个单位各受 N 点伤害，走伤害流程；
  - 阵亡单位在下一个判死时点一起移除。
  - 目前没有卡带湮灭，用单元测试覆盖。
- **基础技能整体替换**：
  - 装备有基础技能时，整体替换角色的普通技能，空心即清空；
  - 改在 `CardDB.combine` 里，目前没有装备带基础技能，所以结果不变；
  - 用单元测试覆盖。
- 完成后去掉 battle-rules.md 里对应的「待实现」标记和第 7 节（动画与跳过顺序不同）。

## 2. 战斗场景改为回放

- **开始战斗**：先用 `BattleSim` 算完整场，再按事件逐个播放，每一步都等动画结束再继续。
- **跳过**：停止播放，直接显示最终状态，包括幸存单位、战力、已消耗的庇护和胜负。
- **速度、实时状态开关**：不变。
- **动画样式**：沿用现有的上前、放技能、飘字、对撞、阵亡淡出和补位，只是改成按事件驱动。
- `battle_manager.gd` 里的结算代码全部删掉，只保留播放。

## 3. 无头命令 `cli/sim.gd`

- 输入 JSONL 文件，每行一场 `{"p1": ..., "p2": ...}`；输出 JSONL，每行一个结果，加 `--log` 时带上事件日志。
- 命令：`just sim <输入> <输出>`。
- 测吞吐量。现在用场景跑，约 100 场/秒；纯逻辑预计快一到两个数量级。这个数字决定以后做强化学习时是否需要更快的实现。
