# 阶段 2 计划：战斗核心

> **状态**：PR A 已完成（2026-11-02），待合并；PR B 待做。issue #7「阶段 2：战斗核心」。执行记录见文末。
> 规则以 [battle-rules.md](../design/battle-rules.md) 为准，本阶段要实现其中标「待实现」的各项。讨论结论见 [decisions.md](../decisions.md) 11-02 的条目。

## 目标

1. **纯逻辑战斗核心** `BattleSim`：不依赖场景节点，一场战斗瞬间算完，输出结果和事件日志。
2. **战斗场景改为回放**：按事件日志播放动画。动画和跳过的结果由同一份结算得出，必然一致。
3. **实现新规则**：
   - 分拍结算，顺序改为先加后减；
   - 平局只保留"连续 20 次交战无人阵亡"，同时修 B9；
   - 湮灭；
   - 装备叠放模型（基础技能整体覆盖，用 `"clear"` 表示"空"）。
4. **无头命令** `cli/sim.gd`：批量模拟，供测试、关卡工具、平衡实验使用。
5. **工具**（PR B）：关卡枚举、Python 平衡实验、圣水补偿校准。

**不在本阶段做**：新卡和三星/四星的复杂机制（阶段 3）、UI 美化。

## 已确认

- **分拍**：
  - 每种技能有固定时点，双方同一拍同时生效，双方都没有的拍才跳过；
  - 普通技能顺序为 狂暴 → 集结 → 振奋 → 腐蚀 → 湮灭；
  - 动画按拍同步出字。
- **扩展方式**：不建通用注册框架，在核心里留出明确的扩展位置（见 1.3）。
- **平局**：
  - 去掉"7 次不变"，只保留"连续 20 次交战无人阵亡"，按交战次数计；
  - 改之前先用大量随机对局验证没有误判。
- **分两个 PR**：A 是战斗核心，B 是工具。

## 1. 战斗核心 `BattleSim`

### 1.1 接口

- 位置：`scripts/core/battle_sim.gd`，纯 GDScript（`RefCounted`），不碰场景节点。
- 输入：双方阵容 `[[角色 id, 装备 id], ...]`，与基线用例格式相同。
- 输出：
  - 结果：胜负，以及双方幸存单位的战力；
  - 事件日志：见 1.4。
- 单位用"座位-初始序号"标识，如 `1-0` 是 P1 原来的第一个。

### 1.2 流程

完全按 [battle-rules.md](../design/battle-rules.md) 第 2 节：

- 时间节点内先特殊技能阶段（现在没有带时机的特殊技能，留空），再按拍结算普通技能；
- 战前阶段不判平局；
- 判死时点不变。

### 1.3 扩展位置

结算集中在下面几处，阶段 3 的复杂机制按特殊技能的作用点挂上去：

| 位置 | 作用 | 阶段 3 可能挂上的效果 |
|---|---|---|
| `CardDB.combine` | 装备合并（叠放模型） | 勇者（装备战力 ×2）、勇者之魂 |
| 时间节点的特殊技能阶段 | 带时机的特殊技能，先于普通技能 | 模仿面具这类"战前做某事" |
| 普通技能触发 | 某单位在某时机执行整组普通技能 | 精灵女王、战神（再走一轮） |
| 单条技能结算 | 每一拍里的一条技能；在场的被动可以改写它 | 地狱之主（振奋转湮灭）、大王花（腐蚀 +5）、猎人 |
| 伤害流程 | 坚固 → 庇护 → 扣战力；伤害带来源（交战、腐蚀、湮灭、反噬） | 神圣精灵（免疫腐蚀） |

### 1.4 事件日志

战斗场景靠它播放动画，测试用它做自洽检查，以后的重播、复盘和 AI 也能用。草案：

| 事件 | 内容 | 动画 |
|---|---|---|
| `start` | 双方初始阵容和每个单位的属性 | 摆好双方阵容 |
| `pre_battle` | 战前第 k 步的双方单位 | 上前 |
| `enter`、`engage` | 交战位触发入场、开始交战 | 上前、蓝字 |
| `beat` | 一拍：技能名，以及双方每个生效单位的变化（增益、伤害、坚固减免、庇护抵挡、结算后的战力） | 这一拍的飘字同时出 |
| `clash` | 双方的攻击值（致命为 10000）和伤害结果 | 对撞 |
| `backlash` | 反噬伤害结果 | 红字 |
| `death` | 阵亡单位 | 淡出，后排补位 |
| `end` | 胜负和原因：一方全灭、连续 20 次交战无人阵亡 | 显示结果 |

- 每个改变战力的地方都带"结算后的战力"，回放直接显示，不用自己再算。
- 日志带版本号，供以后的重播判断版本是否一致。

### 1.5 规则改动

每项单独一个提交，各自核对对基线的影响：

| 改动 | 对基线的影响 |
|---|---|
| 分拍，顺序改为先加后减 | 无。现有效果都是加减，判死又在整步之后 |
| 平局：去掉"7 次不变"，按交战次数计 20 轮，修 B9 | 有变化。已知 B9 影响 random-010、random-041、random-077 三条；靠"20 轮"判平局的用例会多打一轮。逐条核对后重录 |
| 湮灭 | 无。目前没有卡带湮灭，用单元测试覆盖 |
| 装备叠放模型：基础技能整体覆盖；`"clear"` 表示"空"，`{}` 和省略等价 | 无。目前没有装备带基础技能或"空"，用单元测试覆盖 |

**平局规则改动前的验证**：

- 在核心里临时开放参数，跑几千场随机对局；
- 对比"7 次 + 20 轮"和"只有 20 轮"的胜负；
- 把上限放宽到 1000 轮，看被"20 轮"判平局的对局里，有没有本来会分出胜负的；
- 结果写进 PR 描述。有误判就先和你讨论 20 这个数。

## 2. 战斗场景改为回放

- **开始战斗**：先用 `BattleSim` 算完整场，再按事件逐个播放，每一步都等动画结束再继续。
- **按拍出字**：同一拍里双方的飘字同时出。
- **跳过**：停止播放，清掉正在飘的字，直接显示最终状态，包括幸存单位、战力、已消耗的庇护和胜负。
- **变速**：只影响之后的动画。
- **僵持压缩**：
  - 连续几轮完全相同时，显示"僵持中"并跳到结束；
  - 连续 10 次交战无人阵亡后，显示计数，如"无人阵亡 12/20"。
- **实时状态开关**：不变。
- **动画样式**：沿用现有的上前、放技能、飘字、对撞、阵亡淡出和补位。
- `battle_manager.gd` 里的结算代码全部删掉，只保留播放。

## 3. 无头命令 `cli/sim.gd`

- 输入 JSONL 文件，每行一场 `{"p1": ..., "p2": ...}`；输出 JSONL，每行一个结果，加 `--log` 时带上事件日志。
- 命令：`just sim <输入> <输出>`。
- 测吞吐量。现在用场景跑，约 100 场/秒；纯逻辑预计快一到两个数量级。这个数字决定以后做强化学习时是否需要更快的实现。
