> **状态**：实施中，issue #25。第 1 批（PR #26）、第 2 批（PR #27）已完成。执行记录见第 6 节。
> **依据**：规则以 [battle-rules.md](../design/battle-rules.md) 为准（标"待实现"的就是这次要做的，汇总在它的第 9 节）；卡牌数据以设计表 [card-workbook.xlsx](../design/card-workbook.xlsx) 里状态为"设计中"的行为准（序号、英文 id、各格内容都已填好）；设计的来由见 [stage-3-high-stars.md](stage-3-high-stars.md)。
> 规则和设计表有矛盾或没说清的地方，先问用户，不要自行决定。

## 1. 目标和范围

- 实现 60 张角色、38 件装备和它们用到的全部机制，科研模式里能选、能打、回放能看懂。
- 不做：卡图、数值调整、Rust 版、强度测试、关卡、图鉴里的规则说明页（都是之后的事）。
- 数值按设计表原样录入。发现明显过强的组合记下来，不改数值。

## 2. 做法上的约定

### 2.1 结算结构

`BattleSim` 的一个时点改成 battle-rules.md 4.1 的固定步骤：记 → 增 → 删 → 改 → 加 → 减 → 醒 → 被唤醒的一组 → 原本的一组。

- 每种特殊技能登记自己属于哪一步，结算时按步骤依次执行，不按卡写分支。
- 被动挂在事件上：角色触发一轮基础技能时、某个技能结算一下之前和之后。
- 多一轮是把整个步骤循环再走一遍；多一次是某一拍里重复结算。

### 2.2 描述型特殊技能：一种效果一个 id 加参数

同一种效果的卡只是参数不同。现有的 `rally_gain`（队长）、`corrode_boost`（蟾蜍）并入通用的效果，不保留旧 id。下表是建议的划分，id 可以在实现时调整，但要保持"一种效果一个 id"，并同步 battle-rules.md 6.3 和 `data/README.md`。

| 效果 id（建议） | 参数 | 步 | 用到的卡 |
|---|---|---|---|
| `on_trigger_gain` | 技能（或任意）、数值 | 被动 | 队长、头狼、沼泽触手、星辰法师 |
| `on_resolve_bonus` | 技能、数值 | 被动 | 蟾蜍、大王花 |
| `on_resolve_raise` | 技能、数值 | 被动 | 萨满 |
| `extra_resolve` | 范围（自身 / 己方）、技能 | 被动 | 密林射手、幻梦菇 |
| `extra_round` | 范围（自身 / 己方 / 开战时的第 1 位）、时机 | 被动 | 熊猫大侠、精灵公主、精灵女皇、骑士王、金甲虎王、精灵神杖、圣杯、虎尾神鞭 |
| `double_skills` | — | 被动 | 千机之匣 |
| `double_equipment` | — | 合并时 | 千机魔女 |
| `grant` | 时机、对象、词条和数值 | 增 | 圣咏者、彼岸花妖、灾厄草人（神佑可以是它的一个特例，也可以单独实现） |
| `copy_skills` | 时机 | 记 + 增 | 鹦鹉、鹦鹉手偶 |
| `clear_skills` | 时机、对方前几位 | 删 | 美杜莎女王、石化之眼 |
| `raise_skills` | 时机、技能（或全部）、数值 | 改 | 风滚草、神风使、尤姆卡克斯 |
| `gain_half_skill_sum` | 时机 | 记 + 加 | 炼药师 |
| `gain_if_outnumbered` | 时机、数值 | 记 + 加 | 神裁者 |
| `damage_half_strength` | 时机 | 记 + 减 | 沼泽之王 |

- 卡面文字用带参数的翻译模板（`effect.<id>`），不为每张卡单写一句。
- 只有一张卡用的效果也照这个方式做，不特殊处理。以后加新卡，先在 battle-rules.md 6.3 的表里找同类；找不到再加新的 id，并说明它属于哪一步。

### 2.3 数据格式

- 时机格支持多个时机（海德拉、狮鹫骑士、金色蛇首）；带时机的特殊技能也支持多个时机（八百比丘尼、美杜莎女王）。
- 一个角色可以有多个特殊技能（圣僧"坚固3；庇护1"），现有格式已经支持。
- 不需要兼容旧格式，直接改 `data/cards.json` 和 `data/README.md`。

### 2.4 对拍用例

从第 1 批开始，战斗用例存成共享的 JSON，以后 Rust 版读同一份：

- 一条用例：名字、说明、双方阵容（角色 id 和装备 id）、预期结果（胜负、原因、剩下的角色和战斗力）。
- 现有的战斗基线用例迁到这个格式；每条仍然做镜像检查。
- battle-rules.md 里的每个例子、6.3 表里的每条口径，都要有对应的用例。第 4 节列了必须有的。
- 用例用专门的测试卡（单独的测试卡牌文件，数值固定），不用正式卡，这样以后调数值不会让用例失效。另外保留少量用正式卡的冒烟用例，只检查能打完、左右对称，不检查具体数值。

### 2.5 流程

- 一个 issue，四个 PR，按批次顺序合并。每个 PR 开之前先给用户审（推分支、汇报改动和验证方法），用户会亲自试玩。
- 每批都带上最基本的回放表现（飘字能看出发生了什么），第 4 批只做打磨。
- 每批更新 battle-rules.md 的"待实现"标记、`data/README.md`、`tests/README.md`；结算规则变了就把 `BattleSim.VERSION` 加一。

## 4. 必须有的用例

每条都是规则文档里的一个口径。阵容由开发时自己配，能单独体现这一条即可。

**第 2 批**

1. 神佑给的庇护挡下同一步里对方的腐蚀。
2. 协战：对撞之后结算；持有者在交战位时不生效；没有对撞时不生效；多个协战从前往后。
3. 免疫致命：对方致命时按普通对撞算。
4. 多一次：两下分开过庇护（第一下被挡，第二下打中）；蟾蜍对每一下都加，队长类的被动整轮只算一次。
5. 多一轮：带时机的特殊技能也重复（神官在骑士王后面入场，给 4 层庇护）；被唤醒的一组也重走。
6. 多一轮叠加：熊猫大侠加金甲虎王是 3 轮。
7. 精灵公主：只让开战时的第 1 位在战前多一轮；那个角色战前阵亡后，补位的不多一轮；公主自己在第 1 位时没有效果。
8. 换时机和加时机：狂战斧把入场角色变成每次交战触发；狂化血清在交战角色身上没有效果；神使带狂战斧，神佑仍然只在入场。
9. 多个时机：海德拉在战前、入场、每次交战都触发；八百比丘尼在战前和入场各唤醒一次。
10. 覆盖：噬心药剂换掉宿主的基础技能；虚无之心清空宿主的特殊技能；带特殊技能的装备换掉宿主的特殊技能。

**第 3 批**

11. 风滚草入场：先 +3，自己这次就是腐蚀7；没有腐蚀的队友不获得腐蚀。
12. 圣咏者入场：全体获得集结1，自己这次入场就触发集结。
13. 美杜莎女王：双方同时入场时，对方交战位的入场技能不触发；对方的入场唤醒落空；特殊技能不受影响；第 3 位以后的集结值仍被统计。
14. 增 → 删 → 改：同一步里被给予又被清除的技能，结果是没有；清掉的技能不会被加数值加回来；之后再获得则照常。
15. 鹦鹉：变成对方交战位的基础技能，原有的被换掉；对方没有基础技能时不变；读的是面值；这一轮自己触发时就用上。
16. 沼泽之王：伤害是对方当时战斗力的一半，四舍五入；会被庇护挡下；多一轮时每轮重新读，两轮各打一半；双方都有时互不影响。
17. 炼药师：财富值也算；四舍五入。神裁者：对方角色多于己方时才加。
18. 头狼、沼泽触手、星辰法师：按轮算；被唤醒和多一轮各算一次，多一次不算；星辰法师对一个有多条技能的角色只算一次。
19. 萨满：每一下腐蚀之后马上 +1，同一轮的第二下就用新数值；只加有腐蚀的角色。
20. 大王花和蟾蜍一起：加成相加，卡面的腐蚀值不变。
21. 彼岸花妖给的致命、灾厄草人给的反噬在接下来的交战里生效；已有反噬的相加。
22. 千机之匣：读数时 ×2，战斗中获得的数值也翻倍，"伤害 +N"在翻倍之后加，队友统计它的集结值按翻倍后的算。
23. 千机魔女：装备的战斗力和基础技能数值翻倍；带虚无之心时特殊技能被清空，不翻倍。
24. 尤姆卡克斯：所有基础技能 +2，包括财富；只加已有的技能。

## 6. 执行记录

### 第 1 批：结算结构改造（PR #26）

- **结构**：`BattleSim.STEPS` 列出一个时点里特殊技能的七步，每步写属于它的带时机的特殊技能（现在只有"醒"里的唤醒），双方同时结算，每步每个技能记一个 `special` 事件。被动挂在事件上：`_on_trigger`（己方角色触发一轮某个技能时）、`_hit`（腐蚀、湮灭的每一下，先加结算加成）。多一轮、多一次在第 2 批。
- **效果 id**：队长 `rally_gain` → `on_trigger_gain {skill, amount}`，蟾蜍 `corrode_boost` → `on_resolve_bonus {skill, amount}`。参数的种类在 `CardDB.SPECIAL_PARAMS`，加载时校验；卡面文字的模板用 `{参数名}`。
- **数据格式**：时机格写时机的列表（`"timing_1": ["on_enter", "on_engage"]`），带时机的特殊技能写 `{"timings": [...]}`。构筑阶段的卡面上，一格多个时机时缩小字号竖排（排版在第 4 批再看）。
- **用例**：`tests/golden/battles.jsonl` 拆成 `tests/cases/` 下三个文件：
  - `cards.json`：测试卡。把规则用例、单元测试用到的 1★/2★ 正式卡按现在的数值复制成 `t_<id>`，加上原来写在测试脚本里的 4 张；
  - `battles.json`：规则用例（原来的 rule、docx、design 组，加上原来写在单元测试里的 3 条，新增一格多个时机、唤醒带两个时机 2 条），只用测试卡，期望值多了原因和幸存的角色 id；
  - `smoke.json`：正式卡的冒烟用例：关卡的 15 个解（只检查我方胜）和 100 场随机对局（不检查数值）。
- **验收**：
  - 5149 场对局（原来的全部用例加 5000 场随机对局）改造前后的事件日志逐条对比，除了效果 id 改名、时机写成列表、版本号以外完全一致；20000 场随机对局的结果完全一致。
  - `just sim` 单线程（20000 场随机对局，改造前后交替各跑 3 次）：改造前 5696–5776 场/秒，改造后 5752–5835 场/秒，没有下降。被动的持有者按方记下来（判死后更新），没有被动、没有带时机的特殊技能时直接跳过。
  - `BattleSim.VERSION` 4 → 5（事件里的效果 id 和特殊技能的写法变了）。

### 第 2 批：词条类机制和大部分卡（PR #27）

- **机制**：
  - 神佑 `bless {timings, amount}` 在"增"这一步，效果记成"获得"（`grant`，带获得后的层数），以后圣咏者这类获得也用它；
  - 免疫致命 `immune_lethal`：对撞时对方的致命按普通攻击算；
  - 协战 `assist`：对撞之后、反噬之前，第 2 位起从前往后，同一位置双方一个 `assist` 事件；
  - 多一次 `extra_resolve {scope, skill}`：同一拍里接着再结算，效果上标 `again`、`again_by`；
  - 多一轮 `extra_round {scope, timing}`：每个单位按来源数多走几轮，第 2 轮起记 `round` 事件；范围 `self`、`allies`（含持有者自己）、`first`（只看开战时的第 1 位，持有者自己在第 1 位时没有效果）。
  - `BattleSim.VERSION` 5 → 6。
- **卡**：43 张角色、35 件装备按设计表录入（一次性脚本读"设计中"的行）。三个新词条的飘字饰板：协战是交叉的短刀，免疫致命是禁止符压着毒液，神佑是光环罩着小盾。
- **回放**：神佑是金色的光，下一位弹"庇护"、罩上保护罩；协战是橙色光球；多一次多出来的每一下晚 0.3 秒，来源弹卡名；多一轮来源弹卡名，重走的单位收回再发动；免疫致命在对撞时弹词条。
- **界面**：图鉴星级筛选到 5★。科研模式选卡区多了 3★–5★ 三个星级之后，1920 宽时一行放不下，星级、种族的勾选块改成不画勾选框（选中是金框），一行省出约 350。
- **用例**：规则用例加了 21 条（第 4 节第 1–10 条，加上协战的持有者 ≤0、多一次的来源相加、多一轮和多一次相乘），全部先手算、再和引擎对比，一致。原来的"唤醒带两个时机"换成八百比丘尼的版本。随机冒烟用例改成 150 场（卡多了，100 场覆盖不到每件装备 3 次）。
- **发现**：神佑只给下一位，下一位在同一个时点里不会是交战位，所以"神佑的庇护挡下同一步里对方的腐蚀"现在的卡做不到；第 1 条用例改成挡下同一次入场里对方的湮灭（测试卡），规则文档 4.1 写明了。
- **速度**：同样 20000 场 1★/2★ 对局，第 1 批 5615–5764 场/秒，第 2 批 5461–5550 场/秒，慢约 4%（新机制的检查）；全部卡的随机对局约 4900 场/秒（高星对局更长）。
- **试玩修改**：图鉴的星级筛选改回三列（五列把侧栏撑宽到 519，压住了"共 X 张"和第一列卡）；顶栏上移 5，网格的截断线下移到排序、重置筛选下面（原来按钮的下边比截断线低 2，滚动时看着不齐）。冒烟测试加了这两项布局检查。
- **留到第 4 批**：一格三个时机（海德拉、金色蛇首）在构筑阶段卡面上字太小。
