# 阶段 0.5 计划：行为基线测试与规则修复

> **状态**：已完成，待 PR 合并（2026-11-02）。issue「阶段 0.5：行为基线测试与规则修复」，分支 `stage-0.5-baseline`，通过 PR 合并。

## 目标

1. 建一套一键运行的测试，记录**现在**的战斗结果，作为之后整理和重构的对照。
2. 修掉已经确认的规则问题。每项修复的影响都可见、可核对。
3. 弄清两个关卡现在有几个解，修复后又有几个。

**测试原则**：精简、有代表性，避免冗余；随规则、数据和卡牌的改动同步维护。维护方法写在 `tests/README.md`。

**不在本阶段做**：

- 改目录、命名、数据格式（阶段 1）；
- 抽出战斗核心、实现湮灭（阶段 2）；
- 修 UI 小 bug（阶段 1 顺手修）。

## 1. 测试设施

| 文件 | 作用 |
|---|---|
| `justfile` | `just test` 全部测试、`just record` 重录基线、`just levels` 枚举关卡解、`just run` 运行游戏 |
| `tests/run_tests.gd` | 测试入口（无头 SceneTree 脚本）：战斗用例、单元测试、冒烟流程。有失败时退出码非 0 |
| `tests/battle_harness.gd` | 给定双方阵容跑一场战斗，返回胜负和双方幸存单位的战力。复用现有战斗场景，关闭动画 |
| `tests/golden/battles.jsonl` | 战斗用例，一行一条，方便看 diff |
| `tests/tools/record_golden.gd` | 用当前引擎重录期望值，并列出结果变化的用例 |
| `tests/tools/level_solutions.gd` | 枚举关卡的全部摆法，输出解 |
| `tests/README.md` | 测试怎么跑、怎么维护 |
| `.github/workflows/test.yml` | 推送和 PR 时在云端跑 `just test` |

- **错误捕获**：用 Godot 的 `Logger` 收集运行中的错误，测试期间出现任何脚本错误都算失败。
- **超时保护**：脚本出错会让当前协程中断、测试卡住，所以加看门狗，超时即判失败。
- **Godot 路径**：默认 `/Applications/Godot.app/Contents/MacOS/Godot`，可以用环境变量 `GODOT` 覆盖。
- **速度**：现有战斗场景约 30 场/秒，`just test` 预计 10 秒左右。

## 2. 战斗用例（约 130 条）

每条用例包含：编号、分组、双方阵容、期望结果（胜负加双方幸存单位的战力）、备注。

| 分组 | 内容 | 数量 | 期望值来源 |
|---|---|---|---|
| rule | 每条规则 1 条：集结、狂暴、腐蚀、振奋、庇护、坚固、致命、反噬、入场补位、交战重复触发、战前逐对结算、武器时机叠加、特殊技能替换、平局 | 约 15 | 手算，再与引擎核对；不一致先查清原因 |
| docx | `战斗流程.docx` 里的例子 | 1 | 文档 |
| design | 1★ 三张同名卡的循环克制：士兵 > 淤泥怪 > 老虎 > 士兵 | 3 | 录制 |
| level | 两关枚举出的全部解 | 若干 | 录制 |
| random | 固定种子的随机对局：1–7 人，1–2★ 角色，60% 带装备；每个角色、每件装备至少出现 3 次 | 约 100 | 录制 |

- **镜像检查**：每条用例交换左右再跑一次，结果必须镜像对称。修复反噬前已知不对称的用例单独标出，修复后应当全部消失。
- **单元测试**：只给对战用例触发不到的情况写，目前只有"相邻两个单位同时阵亡"一条。

## 3. 冒烟流程

- **科研模式**：主菜单 → 科研模式 → 设置阵容 → 开始战斗 → 跳过 → 返回 → 主菜单。
- **闯关**：关卡选择 → 两关的布阵界面各加载一次 → 开始战斗 → 返回。
- **图鉴**：翻页，按角色、装备、星级、关键词筛选。
- **通过标准**：流程走完，期间没有任何错误。

## 4. 修复顺序（每项一个提交）

| # | 内容 | 预期影响 | 验证 |
|---|---|---|---|
| 1 | 建基线（不改游戏代码）+ CI | — | 本地和 CI 都通过 |
| 2 | 跳过时战前阶段不再真实等待 | 只影响时长 | 结果不变 |
| 3 | 平局：新增"连续 20 轮无人阵亡" | 原本不会结束的对局变成平局 | 新增一条无限战斗用例。这条用例不用圣水，因为第 6 步会改圣水 |
| 4 | 反噬：双方都结算，走伤害流程 | 含反噬的用例 | 结果变化的用例里都必须有豪猪或尖刺拳套；镜像检查全部通过 |
| 5 | 死亡单位一次性移除 | 现有卡牌触发不到 | 单元测试 |
| 6 | 圣水改为仅战前时机，+2 战力 | 含圣水的用例 | 结果变化的用例里都必须有圣水 |
| 7 | 关卡复核 | — | 两关的解数量和通过率，修复前后对比 |

每次修复后用 `just record` 重录基线，工具会列出结果变化的用例。我逐条核对都在预期范围内后再提交。PR 描述里附每一步的变化统计。

## 5. 关卡复核

- **枚举范围**：玩家的所有摆法，包括只上部分角色、装备可以不用。相同的卡互换算作同一种摆法。
- **规模**：猪突猛进约 900 种摆法，虎虎生风更少；每关约半分钟。
- **输出**：解的数量、每个解的具体摆法、通过率。记录到新建的 `docs/design/levels.md`，供阶段 4 设计关卡参考。
- 你记得去掉对称后大约有 1–4 组解。修复反噬后，如果猪突猛进的解数变化很大，再一起讨论怎么调这一关。
