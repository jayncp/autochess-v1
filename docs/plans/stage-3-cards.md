# 阶段 3 计划：卡牌补全（第一轮：1★/2★ 打底）

> **状态**：已确认（2026-11-06），执行中。issue #10。
> 设计稿：[card-workbook.xlsx](../design/card-workbook.xlsx)（用户原稿见提交 `f3e5851`）。讨论结论见 [decisions.md](../decisions.md) 11-06 的条目。

## 目标

1. **统一规范**：术语、显示顺序、分隔符、数据格子、序号。
2. **新机制**：支援、唤醒（第一个带时机的特殊技能）、队长和蟾蜍的条件触发效果、财富（只做特效）。
3. **新卡**：1★/2★ 补齐，共新增 12 张角色、6 件装备；剧毒匕首改为剧毒之牙；仙女加强。卡图先用占位图。

顺序是 规范 → 机制 → 新卡。三步做完后先停下，一起规划卡图、UI、强度测试。

**本轮不做**：
- 卡图；
- UI 调整（只做按字数调字号）；
- 系统的强度测试；
- 3★ 及以上；
- 经济系统（财富不产生金币）。

## 1. 规范

### 1.1 术语

| 术语 | 定义 |
|---|---|
| 角色 | 战斗中的一张卡，可以带装备。卡面只用"角色"，文档里的"单位"同义 |
| 队列 | 一方的全部角色，从前往后排成一列：己方队列 / 对方队列 |
| 位置 | 队列里从前往后数第几位；前面有人阵亡，后面的依次前移 |
| 交战位 | 第 1 位的专称；说"第 1 位""前两位"时都包含交战位。只有双方交战位互相攻击 |
| 下一位 | 紧挨在后面的己方角色；自己在最后一位时没有 |
| 全体 | 某一方队列里的所有角色，含自己 |
| 己方角色 / 己方其他角色 | 前者含自己，后者不含 |
| 己方 / 对方 | 相对卡牌的持有者，不用"我方""敌方" |
| 阵亡 | 判死时点战斗力 ≤0，被移出队列 |
| 战斗力 +N | 增益，不受坚固、庇护影响 |
| 受到 N 点伤害 | 走伤害流程（坚固 → 庇护 → 扣战斗力）。统一写"对方……受到 N 点伤害"，不写"对对方造成 N 点伤害" |
| 触发 | 时机到了，角色的基础技能生效一次 |
| X值 | 技能后面的 N，如集结值、腐蚀值 |
| 基础技能 / 特殊技能 | 原"普通技能"改称基础技能 |

- 不说"在场"：卡面上的被动效果默认只在己方队列中生效，不用写出来；规则文档里需要精确说法时，写"在队列中（含战斗力 ≤0、还没判死的）"。
- 保留"入场"这个名字，含义是第一次成为交战位时。
- 句子省略对象时指自身；需要强调时写"自身"。

### 1.2 词条说明（句式）

| 词条 | 说明 |
|---|---|
| 狂暴N | 自身战斗力 +N |
| 集结N | 自身战斗力 + 己方全体的集结值之和（没有时机的也算） |
| 支援N | 下一位角色战斗力 +N |
| 振奋N | 己方全体战斗力 +N |
| 腐蚀N | 对方交战位受到 N 点伤害 |
| 湮灭N | 对方全体各受到 N 点伤害 |
| 财富N | 获得 N 金币（本轮只有特效） |
| 反噬N | 每次交战后，自身受到 N 点伤害 |
| 坚固N | 每次受到的伤害 −N（最低为 0，优先于庇护） |
| 唤醒 | 触发下一位角色的基础技能 |
| 庇护 | 抵挡一次伤害 |
| 致命 | 交战时攻击视为无穷大，可被庇护抵挡 |

- 说明以文本形式写进翻译表（`keyword_desc.<id>`）。显示说明的界面放到 UI 阶段。
- **描述型特殊技能**不起词条名，卡面直接写整句，比如队长、蟾蜍的效果。
  - 内部仍有英文 id 和数值，供代码使用，玩家看不到；
  - 句子是带 N 的翻译模板。

### 1.3 顺序（代码里各只定义一处，卡面、实时状态、图鉴共用）

- **基础技能**按结算顺序，作用对象由近及远：狂暴 → 集结 → 支援 → 振奋 → 腐蚀 → 湮灭 → 财富。
- **特殊技能**按所属种族排，同族内基础特殊技能在前：反噬 → 坚固 → 队长效果 → 唤醒 → 庇护 → 致命 → 蟾蜍效果。
- **种族**：动物 → 人族 → 精灵 → 神族 → 自然（基础五族）→ 财宝。
  - 以后的扩展种族编号排在后面，它们的词条可以插在结算顺序中间。
  - 对战模式里，扩展种族可以作为扩展选择性加入。
- **时机**：战前 → 入场 → 交战（不变）。
- 数据里怎么写都可以，显示时统一按上面的顺序排。

### 1.4 分隔符

- 种族、时机、基础技能之间用"、"，如"动物、人族""战前、交战""狂暴2、集结1"。
- 特殊技能之间用"；"；带时机的写"时机：效果"，如"战前：唤醒；致命"。
- 全角符号更宽，标签按字数自动缩小字号。卡面布局到 UI 阶段再整体调整。

### 1.5 格子模型

装备像一张卡盖在角色卡上，逐格处理：装备那一格有内容就覆盖，空着沿用角色的，写"空"（`"clear"`）清空。处理完再把两格合并。

| 格子 | 数据字段 | 合并 |
|---|---|---|
| 战斗力 | `strength` | 不分格：角色的加上装备的，装备不覆盖角色的战斗力 |
| 时机-1 / -2 | `timing_1` / `timing_2` | 两格取并集；每个时机都触发全部基础技能 |
| 基础技能-1 / -2 | `skills_1` / `skills_2` | 两格同名数值相加 |
| 特殊技能 | `special_skills` | 只有一格，整体覆盖 |

- 角色和装备都能填任意格。通常角色填 1、装备填 2，效果就是叠加；装备填 1 就是覆盖角色那一格，比如空心的"基础技能-1：空"。
- 字段改名对照：

  | 原字段 | 新字段 |
  |---|---|
  | `timing` | `timing_1` |
  | `weapon_timing` | `timing_2` |
  | `skills` | `skills_1` |
  | `weapon_skills` | `skills_2` |
  | `weapon_strength` | `strength` |

- 代码里的 `normal_skills` 改为 `base_skills`。事件日志格式变了，所以 `BattleSim.VERSION` 升到 2。
- 设计表的"角色""装备"两张表改用同一套格子列。

### 1.6 序号与排列

- 序号是 4 位数，依次是类型（1 角色、2 装备）、星级、两位流水号，主要用于图鉴顺序。
- 同星级先按设计分组，组内按种族顺序；双种族卡先比第一个种族，再比第二个。
- `cards.json` 也按这个顺序排。

## 2. 新机制

### 2.1 支援N（基础技能）

- 在支援拍，给触发时的下一位 +N；自己在最后一位时不生效。
- 每触发一次加一次，挂在交战时机上就是每次交战都加。

### 2.2 唤醒（带时机的特殊技能）

- 时机属于特殊技能本身，和卡牌的时机无关。
  - 闪光球装在交战角色身上，也只在战前唤醒；
  - 数据里写成 `"special_skills": {"awaken": {"timing": "pre_battle"}}`。
- 在该时间节点的特殊技能阶段，双方同时触发，相当于插入一次触发：下一位角色的整组基础技能（包括装备给的）作为"被唤醒的一组"，在原本的一组之前结算（时点结构见 `battle-rules.md` 2.1，11-07 定）。时点中途不判死。
- 被唤醒的角色自己的时机照常触发。没有时机的角色也能被唤醒，比如唤醒大将军就会触发他的集结5。
- 不连锁：只触发基础技能，不触发下一位自己的唤醒。
- 例：光灵在第 1 位，精灵虎在第 2 位。
  1. 战前第 1 步，光灵唤醒精灵虎，精灵虎狂暴 +9；
  2. 战前第 2 步，精灵虎自己的战前时机再 +9，一共 +18。

### 2.3 条件触发的特殊技能

都是被动：持有者在队列中就生效。效果都叠加，持有者自己触发也算，同名卡各自生效。

| 卡 | 效果 | 结算 |
|---|---|---|
| 队长 | 己方角色触发集结时，自身战斗力 +2 | 在集结拍，每有一个己方角色触发集结，队长 +2 |
| 蟾蜍 | 己方角色触发腐蚀时，腐蚀值 +2 | 腐蚀5 实际按 7 进入伤害流程 |

- 蟾蜍的效果写"腐蚀值 +2"，不写"伤害 +2"：后者会被读成在坚固之后加。
  - 例：腐蚀2 打在坚固4 的盾卫身上，按"腐蚀值 +2"是 (2+2)−4 = 0；按"伤害 +2"是 0+2 = 2。
- 唤醒、以后的"多一次""多一轮"带来的触发，也会触发这两个效果。

### 2.4 财富N（基础技能，只做特效）

- 财富是最后一拍：触发时在卡上飘黄色 +N，不记金币，不影响胜负。
- 以后交战财富可能要加上限，因为可以构造出双方都不掉血、一直叠财富的局面。

### 2.5 战斗演出

演出只做到能看清结算的程度，正式美术留到 UI 阶段：

| 效果 | 演出 |
|---|---|
| 支援 | 和其他增益一样，在下一位身上飘字 |
| 唤醒 | 光灵飘"唤醒"，被唤醒的角色出列、出手、收回，然后原本的角色出手 |
| 队长 | 集结拍里在队长身上飘"队长 + 2"（来源卡名，带数字因为改了战斗力） |
| 蟾蜍 | 腐蚀飘字显示加成后的数值，蟾蜍身上只弹"蟾蜍" |
| 财富 | 黄色 +N |

## 4. 执行步骤

一个 PR 内容太多时，执行中再拆细。

**PR 3a 规范**：只改名称和格式，不改规则。验收标准是所有基线用例结果不变（`venom_dagger` 改 id 后同步迁移）。
1. **数据**：
   - 字段按 1.5 改名；
   - `cards.json` 按 1.6 重排、重编序号；
   - 剧毒匕首改为剧毒之牙 `venom_fang`，卡图文件先跟着改名，等重画。
2. **`CardDB`**：
   - 顺序常量按 1.3；
   - 合并改为逐格循环；
   - `normal_skills` → `base_skills`。
3. **卡面**：
   - 分隔符按 1.4；
   - 按字数缩小字号；
   - 卡图缺失时用占位图 `assets/cards/placeholder.png`（用户给的像素鸟，缩到 256×256）。数据检查会列出哪些卡在用占位图，不算失败。
4. **`BattleSim`**：字段改名，`VERSION` 升到 2。
5. **工具和测试**：
   - Python 工具的字段同步；
   - 基线用例中的 `venom_dagger` 改为 `venom_fang`；
   - 截图检查卡面。
6. **文档**：
   - 术语和词条说明写进 `battle-rules.md` 第 1、3、4 节，第 6 节按格子模型重写；
   - `game-design.md` 的种族表按新顺序；
   - 翻译表加现有词条的 `keyword_desc`；
   - 同步 `AGENTS.md`。
7. **设计表**：
   - 改成格子列，按 1.6 排序并填上序号；
   - 设计行的"状态"补成"设计中"；
   - "词条"表换成 1.2 的句式；
   - 应用已定的修改（蛇人 6、项链 2★）。

**PR 3b 机制**（可能拆成 3b-1 支援和财富、3b-2 唤醒和条件触发）：
1. 支援、财富两拍。
2. 唤醒：
   - 特殊技能阶段第一次真正用上；
   - 数据格式按 2.2；
   - 新增事件 `special`。
3. 队长、蟾蜍的效果：挂在"单条技能结算"这个扩展位置上。
4. 事件日志、回放演出按 2.5。
5. **测试**：
   - 每个机制用测试专用卡（`CardDB.add_cards`）写单元测试，覆盖上面的例子和边界：最后一位支援、唤醒没有时机的角色、同名卡叠加、唤醒触发队长和蟾蜍；
   - 镜像检查和回放检查都要覆盖。
6. **文档**：更新 `battle-rules.md`。

**PR 3c 新卡**：
1. 按第 3 节录入数据和中文名，卡图用占位图。
2. 测试：
   - 每张新卡至少一条规则用例进基线；
