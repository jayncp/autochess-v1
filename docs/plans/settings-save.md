# 设置和存档计划

> **状态**：计划（2026-11-10），内容已和用户讨论确定，开工前开 issue，一个 PR 完成。

## 目标

- **设置页面**：
  - 默认速度、默认紧凑模式；
  - 显示存档位置，让玩家找得到；
  - 清除闯关记录。
- **存档**：
  - 固定的存档目录 `niuma_autochess`；
  - 设置和进度分两个文件；
  - 接上闯关的通关记录。

**不做**：

- 修改存档位置；
- Android 的存档导入导出（以后再说）；
- 关卡解锁；
- 通关成绩（次数、最少上场人数这类）；
- 云同步、加密。

以后要存的内容（冒险进度、金币、回放等）到时再定，存档格式带版本号，加内容时升级。

## 1. 存档位置

Godot 的存档目录是 `user://`。默认按项目名放在 `Godot/app_userdata/自走棋v1/` 下，路径里有"Godot"，还跟着临时游戏名走。改成自定义目录：

- `application/config/use_custom_user_dir=true`
- `application/config/custom_user_dir_name="niuma_autochess"`

| 平台 | 存档位置 |
|---|---|
| Windows | `%APPDATA%\niuma_autochess\` |
| macOS | `~/Library/Application Support/niuma_autochess/` |
| Linux | `~/.local/share/niuma_autochess/` |
| Android | 应用内部存储（`/data/data/<包名>/files/`），玩家看不到，卸载时一起删除 |

- **改名之后**：以后游戏改名，存档目录不变。原来的 `自走棋v1` 目录里只有引擎的日志和缓存，没有存档，不用迁移。
- **编辑器运行**：从编辑器运行（`just run`）时，用的也是这个目录，所以本机试玩的记录就是正式记录。
- **测试**：用单独的文件名，不读写玩家的存档。
- **Android 包名**：现在还是占位的 `com.example.autochess`，正式发布前要定下来。之后再改就等于换了一个应用，存档会丢。

## 2. 文件

| 文件 | 内容 | 格式 |
|---|---|---|
| `settings.cfg` | 默认速度、默认紧凑模式 | Godot 的 `ConfigFile`（文本）；缺的项用默认值，不认识的项忽略 |
| `save.json` | 进度：闯关的通关记录 | JSON，带版本号 |

`save.json` 的结构：

```json
{
  "version": 1,
  "levels": {
    "<关卡 id>": {"cleared": true, "first_cleared": "2026-11-10T12:00:00"}
  }
}
```

- **写入**：写坏了也能恢复。
  1. 先写到 `save.json.tmp`；
  2. 原来的 `save.json` 改名为 `save.json.bak`；
  3. 再把 `.tmp` 改名为 `save.json`。
- **读取**：
  - `save.json` 读不了或解析失败：读 `.bak`，主菜单弹通知"存档读取失败，已用备份恢复"；
  - 备份也不行：从空进度开始，坏的文件改名为 `save.json.broken` 留着，通知"存档读取失败，进度已重置"。
- **版本**：
  - 读到旧版本时按版本号逐级升级，下次保存时写成新版本；
  - 读到比游戏更新的版本（旧游戏打开新存档）时，只读不写，免得把新内容覆盖掉。

## 3. 设置页面

- **入口**：主菜单"图鉴"下面一项"设置"。
- **布局**：和其他界面一路，左上角返回，标题"设置"，下面分组：

  | 分组 | 项 | 控件 |
  |---|---|---|
  | 战斗 | 默认速度 | 1×、2×、5×、20× 四个单选按钮 |
  | 布阵 | 紧凑模式（默认打开） | 开关 |
  | 存档 | 存档位置 | 只读的路径框（可以选中）、"复制路径"、"打开文件夹"（只在 PC 上有）；手机上不显示按钮，改成一行说明"存档在应用内部，卸载游戏会一起删除" |
  | 存档 | 清除闯关记录 | 按钮，弹确认对话框（"清除闯关记录 / 所有关卡的通关记录都会清除，设置不受影响。"，"取消" + "确定"）；只清进度，不动设置 |

- 改了立刻生效、立刻保存，没有"保存"按钮。
- **默认值什么时候用**：每次进入时读一次，当次可以临时改，临时改的不写回设置。
  - **构筑阶段**：每次从关卡选择进入时读默认紧凑模式；
  - **科研模式**：每次从主菜单进入时读默认紧凑模式；
  - **战斗**：每场开战时读默认速度。
  - 从战斗返回构筑阶段或科研模式，不算重新进入，保持刚才临时切的紧凑模式。
  - 构筑阶段和科研模式不再共用临时的紧凑模式（现在是"这次运行里一直保持"）。

## 4. 闯关记录

- **什么算通关**：只有赢了才算（我方胜）；平局、失败不算；科研模式的战斗不记。
- **记什么**：只记"已通关"，内部顺带记下第一次通关的时间（不显示）。
- **怎么显示**：关卡选择里已通关的关卡显示绿框加右上角绿色对号。样式已经做好（`level_tile.gd`），现在接上数据。
- **解锁**：不做，所有关卡一直都能进。
- **实现**：
  - 开战时记下这场来自哪个关卡（`global_var` 里加一项，科研模式为空）；
  - 显示胜负时，如果是关卡且我方胜，写进存档；
  - 回到关卡选择时刷新。

## 5. 实现

- **设置**：`scripts/core/game_settings.gd`（`GameSettings`，静态类，和 `global_var` 一样不用 autoload）。
  - 两项：`speed`、`compact`；
  - `load()` 在启动时调用一次（场景管理器），`save()` 在设置改动时调用；
  - 文件路径是静态变量，测试里改掉。
- **进度**：`scripts/core/save_data.gd`（`SaveData`，静态类）。
  - 接口：`load()`、`save()`、`is_cleared(关卡)`、`mark_cleared(关卡)`、`clear_levels()`；
  - 版本升级、备份恢复；
  - 读取失败的提示交给主菜单显示；
  - 文件路径同样可以改。
- **设置界面**：`scenes/settings/settings.tscn`、`settings.gd`。
  - 打开文件夹用 `OS.shell_show_in_file_manager`，复制用 `DisplayServer.clipboard_set`；
  - 是否 PC 按平台判断（`OS.has_feature("mobile")`，和看卡的悬停、长按一致）。
- **接上去的地方**：
  - 场景管理器：启动时读设置和进度，主菜单的"设置"，进入构筑阶段、科研模式时把紧凑模式设成默认值；
  - `battle_manager`：开战速度读默认值，结束时记通关；
  - 关卡选择：读通关记录。
- **翻译**：`ui.menu.settings`、`ui.settings.*`。
- **项目设置**：自定义存档目录（第 1 节）。
- **测试**：
  - 设置读写往返；
  - 进度读写往返；
  - 主文件坏了读备份，备份也坏了从空进度开始；
  - 旧版本升级，新版本只读；
  - 冒烟流程：闯关打赢后关卡选择显示已通关，清除记录后消失；进入构筑阶段、科研模式时紧凑模式是默认值。
  - 以上都用测试专用的文件名。
- **文档**：
  - `art-direction.md` 加设置页面；
  - 存档格式写进新的活文档 `docs/design/save-data.md`（文件、字段、版本、升级规则），以后加存档内容就更新它；
  - AGENTS、PROCESS。
