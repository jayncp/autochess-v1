## 平衡

| 日期 | 决定 |
|---|---|
| 11-02 | **核心理念"大毒盾"**：大克盾、盾克毒、毒克大 |
| 11-02 | 星级平衡原则；各档角色有效战力均值 6/13/21/30/40 |
| 11-02 | **角色和装备各自平衡，不按星级互相折算**（装备不占人口，获取方式也不同） |
| 11-02 | 接受 2★ 略强于 2×1★ |
| 11-02 | 同族集中组队的强弱差异来自种族定位不同（人族群体集结、动物一打多、自然机制杀、精灵功能性、神族增益和防守），暂不调整 |

## 战斗规则

| 日期 | 决定 |
|---|---|
| 11-01 | **反噬**：修复短路 bug，双方都结算；走伤害流程，坚固减免、庇护可挡（与 Python 一致） |
| 11-01 | **湮灭**：实现；克制庇护是有意设计，只出现在最高星级，以后会增加额外获得庇护的手段 |
| 11-01 | **特殊技能**：装备整体替换角色的，不叠加。致命+庇护叠加是天花板级机制 |
| 11-01 | 基础技能整体替换、致命可被庇护挡下、无时机技能只作被统计的数值（默认） |
| 11-02 | **坚固是特殊技能，随特殊技能整体替换**，一个单位只有一个坚固值（撤销此前默认的"多个坚固求和"）。以后如果有机制在特殊技能之外额外给予坚固，再定叠加方式 |
| 11-01 | ~~**平局**：保留"连续 7 次全场战力不变"，新增"连续 20 轮无人阵亡"~~（已被 11-02 取代）。核实结果：旧代码各版本都是 7 次，Python 是 100 轮上限，没有 10/30 回合的规则 |
| 11-01 | **羁绊、三合一升星暂不做**；以后服务于冒险、对战这类长程玩法 |
| 11-02 | **分拍结算**：每个时间节点先走特殊技能阶段（双方同时，需要时之后判死），再按拍走普通技能。每种技能有固定时点，双方同一拍同时生效，双方都没有的拍跳过。动画按拍同步出字 |
| 11-02 | **普通技能顺序改为先加后减**：狂暴 → 集结 → 振奋 → 腐蚀 → 湮灭。避免同一步里先被打到 ≤0、又被振奋"复活"的观感；现有卡结果不变 |
| 11-02 | **特殊技能**：无时机的是被动，在场（含 ≤0 未移除）就生效，离场即失效（地狱之主按此实现，不再开战前统一转换）；带时机的先于普通技能触发。作用点：装备合并、时间节点、普通技能触发、普通技能结算和伤害流程；局外另定 |
| 11-02 | 转化来的技能并入目标技能那一拍结算、数值合并，卡面分开显示、换颜色；"再触发一次"（原精灵女王）是整组普通技能再走一轮，不是数值 ×2 |
| 11-02 | **战斗中获得的词条叠加**，不覆盖；整体替换只发生在装备合并时 |
| 11-02 | **平局只保留"连续 20 次交战无人阵亡"**，去掉"连续 7 次战力不变"；按交战次数计，入场不算。已用 20000 场随机对局验证没有误判（见 plans/stage-2-battle-core.md 执行记录）。同时修 B9（战前阶段也在累计"7 次不变"，6 人以上、没有战前效果的对局一开打就平局） |
| 11-02 | 冒险、对战模式的平局怎么结算（如比剩余战力），到设计局外规则时再定 |

## 架构与工程

| 日期 | 决定 |
|---|---|
| 11-01 | **战斗抽成纯逻辑模块**，表现层回放；无头模拟、关卡验证、平衡测试都基于它 |
| 11-02 | 三星扩展先不建通用注册框架，只在核心里留明确的扩展位置；特判多到难维护时再抽象 |
| 11-01 | 先用 GDScript 写唯一的一份实现，测完吞吐量再决定是否需要 Python 镜像（默认） |
| 11-01 | **整理和重构之前先建行为基线测试**；已确认的规则 bug 先修，再冻结基线 |
| 11-02 | Python 工具与 Godot 同仓库：Python 放 `tools/`（带 `.gdignore`，用 uv 管理），GDScript 无头命令放 `cli/`；`.venv`、实验输出、模型权重不进 git（默认） |
| 11-02 | **游戏数据用 JSON**（`data/`），翻译用 CSV（`i18n/`），暂不引入数据库。以后存档放 `user://`（JSON 或 ConfigFile），大规模模拟记录由 `tools/` 的 Python 处理（默认） |
| 11-02 | **开发流程**：首次提交之后，阶段性开发任务走 issue + PR；小修改直接提交到 main |
| 11-02 | **测试原则**：精简、有代表性，避免冗余；随规则、数据、卡牌的改动同步维护。GitHub Actions 在推送和 PR 时自动运行 |

### 协议说明

- 诉求：任何人都能免费使用、可以商用；别人基于它做的东西，你也要能用。第二点只有 copyleft（传染性）协议能保证。
- **先紧后松**：你是版权人，以后随时能把新版本改成更宽松的协议。反过来，已经以宽松协议发布的版本就收不回来了。前提是在接受外部贡献之前改，或者让贡献者签 CLA。
- 你**不受自己协议的约束**，可以把自己的作品用在任何项目里，包括闭源商用。
- copyleft 给你的是"按同一协议使用别人的修改"，不是无条件的使用权。
- 纯 AI 生成的图片在部分法域可能不受版权保护；游戏机制和规则本身也不受版权保护。
