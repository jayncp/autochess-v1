# 02 战斗规则：设计文档 / Python 脚本 / Godot 三方对照

> 目的：把散落在 `战斗流程.docx`、`自走棋规则.xlsx`、旧 Python 脚本和 Godot 代码里的战斗规则合成一份，标出三者差异和待拍板的地方。
> 约定：**数值和名称以 Godot 为准**；Godot 没有实现的机制，参考 Python（它是规则的程序化规范，且经过验证）。
> 原文转录：[source/battle_flow.md](source/battle_flow.md)、[source/rules.md](source/rules.md)。

## 1. 基本概念

| 概念 | 说明 |
|---|---|
| 战斗力 | **唯一数值**，既是攻击也是血量。受伤扣它，交战时也用它当攻击值 |
| 队列 | 每方最多 7 个角色，按顺序排列；第 1 位是**交战位**，只有交战位之间互相攻击 |
| 角色 + 装备 | 每个位置 1 个角色 + 最多 1 件装备（Godot 与 Python 均如此；docx 只说"决定角色与装备顺序"） |
| 星级 | 稀有度档位（1–3★），**不是升星**。Python 另有"大X"三合一（数值 ×2、星级不变），Godot 未实现 |
| 时机 | `战前`（战役前）/ `入场` / `交战`（交战前，**每次交战都触发**）/ `出售`（战斗内不触发）。无时机的角色技能只作为"被统计的数值"（如大将军的集结5） |
| 普通技能 | 带数值、在时机触发：集结 / 狂暴 / 腐蚀 / 振奋 / 湮灭 / 财富 |
| 特殊技能 | 常驻被动：致命 / 坚固N / 反噬N / 庇护，以及三星卡的文字效果 |

## 2. 单场战斗流程

docx 原文 4 步 + 13 步例子；Python 与 Godot 都按此实现。**Godot 实测能复现 docx 例子**（P2 胜、老虎剩 2，左右镜像结果对称）。

```
0. 准备：装备叠加到角色（Python 还先结算羁绊、地狱之主）
1. 战前阶段：第 k 步取双方各自第 k 个存活单位（不论有无战前时机），
   有战前时机的执行普通技能，P1 先 P2 后；每步后统一判死
2. 循环：
   a. 判胜负
   b. 若任一方交战位单位有"未触发的入场" → 双方各自执行入场技能（P1 先），判死，回到 a
      （入场打死对方首位时，对方下一位先入场再交战）
   c. 交战位单位若有交战时机 → 执行普通技能（P1 先），每次交战都触发
   d. 若双方交战位战力都 > 0 → 同时互相造成等于自身战力的伤害（致命另算）
   e. 反噬
   f. 判死、补位，回到 a
```

存活的一方**留在交战位**，伤害不恢复、不会再次入场。

## 3. 普通技能

触发时**固定顺序**：狂暴 → 集结 → 腐蚀 → 振奋 →（湮灭）。Godot `battle_manager.gd:665-675`，Python `main_script.py:319-324`。

| 技能 | 规则原文（规则.xlsx） | 实际实现（Godot 与 Python 一致，除注明） | Godot |
|---|---|---|---|
| 集结N | 己方队列中每一点集结使其战斗力+1 | 自身 + **己方当前队列所有单位集结值之和**（含自己、含无时机单位） | ✅ |
| 狂暴N | 战斗力加N | 自身 +N，永久叠加 | ✅ |
| 腐蚀N | 对方交战位战斗力减N | 对方队列**第 1 位**受 N 点伤害（走伤害流程，受坚固/庇护影响）。战前阶段也打对方第 1 位 | ✅ |
| 振奋N | 己方队列中所有角色战斗力加N | 己方全体（含自己）+N，是加成不是伤害 | ✅ |
| 湮灭N | 对方队列中所有角色战斗力减N | 对方每个单位各受 N 点伤害 | ❌ 未实现 |
| 财富N | 获得N金币 | 己方金钱 +N（只取第一个财富条目） | ❌ 未实现（无经济系统） |

## 4. 特殊技能（被动）与伤害流程

伤害流程（Godot `settlement_damage` `:484-516`，Python `:232-244`）：

```
damage = max(0, damage - 坚固)
if 有未消耗的庇护 and damage > 0: damage = 0, 消耗庇护
strength -= damage
```

| 词条 | 规则原文 | Python | Godot | 差异 |
|---|---|---|---|---|
| 坚固N | 受到伤害减少N | 所有坚固**求和** | 取**最后一个**坚固值 | 目前没有单位同时有两个坚固，暂不影响 |
| 庇护 | 抵挡一次伤害 | 在坚固之后判定，挡 >0 的伤害一次 | 同左（从技能列表移除） | 一致 |
| 致命 | 交战后对方直接阵亡 | 攻击值 = 对方战力 + 100，**会被庇护挡** | 攻击值 = 10000，**会被庇护挡** | 效果一致 |
| 反噬N | 交战后战斗力减N | 只在实际交战后；**走伤害流程**（坚固减免、庇护可挡） | 只在实际交战后；**直接扣战力**，不受坚固/庇护影响 | **语义不同**；且 Godot 有短路 bug（见 01 文档 B1）。**决定：按 Python** |

## 5. 死亡、胜负、平局

| 项 | Python | Godot |
|---|---|---|
| 判死时点 | 每个战前步骤后、每次入场后、每次交战后统一判死；时点之间 ≤0 的单位仍在队列（可触发技能、吃振奋、被自己的狂暴"救活"） | 同左 |
| 移除 | 列表推导，一次移除全部 | 边遍历边 `erase`，**相邻两个同时死亡会漏掉第二个**（已用最小脚本验证 GDScript 行为）。目前每方每次最多死首位一个，暂不触发；实现湮灭后会出问题 |
| 胜负 | 一方空另一方非空即胜；双方同时空 = 平局 | 同左 |
| 防死循环 | 主循环超过 100 轮判平局（入场迭代也算一轮） | 双方战力列表**连续 7 次检查不变**判平局；**没有回合上限** |
| 胜利"伤害" | 胜方存活单位星级之和 + 雷神加成（为多人模式扣士气准备） | 无 |

## 6. 装备叠加规则

`自走棋.tbs` 卡面模板把装备分成"基础(替换)"和"武器(叠加)"两组字段，Python 与 Godot 都按这个语义实现：

| 装备字段 | 语义 | Python `apply_equipment_to_character` | Godot（`load_card` + `battle_manager`） |
|---|---|---|---|
| 武器战力 | 加到角色战力 | ✅（勇者再 ×2） | ✅ |
| 基础时机 | 替换角色时机 | ✅（目前没有装备使用） | ✅（通过覆盖 `time_1` Label 间接生效；目前没有装备使用） |
| 基础技能 | **整体替换**角色普通技能（项链、空心=清空、噬心药剂） | ✅ 整体替换 | ⚠️ 按技能名逐个覆盖，只有空心的 `[]` 会清空；噬心药剂被写进了"武器技能"（叠加） |
| 特殊技能 | **整体替换**角色特殊技能 | ✅ | ✅（实测 盾卫+圣盾 只剩庇护） |
| 武器时机 | 与角色时机取并集；**每个时机都执行全部普通技能**（如 士兵+圣水：战前、入场各执行一次 集结2+振奋1） | ✅ | ✅ |
| 武器技能 | 同名数值相加，否则追加 | ✅ | ✅ |

> ⚠️ "特殊技能整体替换"对三星卡影响很大：精灵女王/战神/大王花/地狱之主等的核心能力写在特殊技能里，装上圣盾、剧毒匕首这类装备就会丢失。旧规则就是如此，但实现三星卡前需要确认要不要改成"叠加"。

## 7. 羁绊（只在 Python 和 `自走棋.xlsx` 中存在）

> **决定：暂不实现**。以后服务冒险模式、对战等长程玩法，可能以其他形式引入。以下仅作参考。

Godot 未实现，docx 和规则.xlsx 也没提。按单位个数计（同名单位重复计）：

| 种族 | 4 个 | 7 个 | Python 与 xlsx 差异 |
|---|---|---|---|
| 财宝 | 战斗结束后 +3 金币 | 财富 +1 | Python 在战前加 |
| 人族 | 人族战力 +2 | 人口上限 +1 | — |
| 动物 | 动物狂暴 +2 | 动物战力 +6 | **Python 为 +3 / +10** |
| 自然 | 自然腐蚀 +2 | 战前我方首位获得致命 | — |
| 神族 | 战前我方首位获得庇护 | 神族振奋 +1 | — |
| 精灵 | 精灵战力 +2 | 我方首位战前效果额外触发 1 次 | — |

Python 结算顺序：羁绊 → 地狱之主 → 装备。所以羁绊只加成角色**自带**的技能。另外，自然 7/神族 4 会把致命/庇护追加到首位**装备**上，导致首位角色原有特殊技能被覆盖（Python bug）。

## 9. Godot 与 Python 的差异汇总

| # | 项 | Python | Godot | 建议 |
|---|---|---|---|---|
| D1 | 反噬伤害 | 走伤害流程（坚固/庇护生效） | 直接扣，且有短路 bug | 修 bug；语义待定 |
| D2 | 平局判定 | 100 轮上限 | 连续 7 次战力不变 | 两者都保留：不变检测 + 硬上限 |
| D3 | 坚固叠加 | 求和 | 取最后一个 | 定为求和 |
| D4 | 基础技能替换 | 整体替换 | 按名覆盖 | 实现项链/噬心药剂时统一 |
| D5 | 死亡移除 | 一次性 | 边遍历边删 | 修为一次性 |
| D6 | 结算顺序 | 同步、确定 | 动画模式下双方技能交错、伤害可能延迟 0.1–0.2s | 抽离纯逻辑层后自然消除 |
| D7 | 羁绊 / 湮灭 / 财富 / 三星特殊 | 有 | 无 | 按路线图补齐 |
