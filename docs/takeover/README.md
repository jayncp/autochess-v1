## 2. 现状一句话

Godot 项目有完整的主流程：主菜单、科研模式（自由摆阵对战）、闯关模式（2 个解谜关，拖拽布阵）、图鉴，以及带速度/跳过的战斗演出；冒险模式和线下对战只有按钮。已实现 15 个角色 + 13 个装备（1–2★），另有 7 个三星角色、10 件装备的数据写好但被注释。

## 3. 关键发现

1. **战斗结果是确定性的**，Godot 能复现 `战斗流程.docx` 的例子；规则与 Python 脚本基本一致，差异列在 [02 第 9 节](02-battle-rules.md#9-godot-与-python-的差异汇总)。
2. **一个已复现的 bug**：反噬结算用了 `or` 短路，同一对局交换左右后结果不同（P1 豪猪 vs P2 小精灵+尖刺拳套 → P2 胜；交换后平局）。关卡"猪突猛进"受影响。另有一个潜伏 bug：死亡移除会漏删，实现湮灭（群体伤害）后会触发。后续做数值实验时又发现一个：**战斗可能无限进行**（没有回合上限，开着"跳过"时会卡死），见 01 文档 B7。
3. **战斗逻辑和 UI 强耦合**：战力从 Label 文本解析，结算里夹着动画和计时器。可以在无头模式下跑，但每场都要实例化整套 UI，且战前阶段有不受"跳过"控制的真实等待 → **做关卡验证/平衡测试/RL 之前，必须先把战斗抽成纯逻辑核心**。
4. **数据三方分叉**：Godot 基本照"待录入"最新表录入，但豪猪反噬 4（表里 2）、圣水多振奋1、奔狼图腾改名尖刺拳套；Python 是更早的平衡版本。
5. **装备按"来源角色 → 衍生装备"出图**：8 张只有图没有数据的卡（队长、蟾蜍、竖笛、森灵头带、穿云弓、藤鞭、腐蚀之爪、双节棍）是生图过程文件，不是待实现的卡（已确认，见 [../decisions.md](../decisions.md)）。
6. **你提到的关卡枚举脚本**是 `自走棋辅助/single_loop_test_launcher.py`，样例正是"虎虎生风"（通过率 3.47%）；但它关掉了羁绊，最优阵容搜索还有丢弃战前结果的 bug。
7. **局外规则**（回合表、人口、商店星级、价格、利息、选秀、拍卖、卡池数量、羁绊）在规则表和 `自走棋.xlsx` 里是齐的，冒险模式和线下对战可以直接以此为蓝本；生命值/士气、出售、玩家人数没有定义。
8. **美术**：36 张卡图走的是 ChatGPT → PS → 256px PNG-8 流水线，有锯齿和半透明丢失；主菜单背景被横向拉伸约 18.5%。
9. **远程仓库 `jayncp/autochess-v1` 已存在，为空，且是 PUBLIC**。
