# 战斗规则

> 活文档：战斗核心的规则规范，测试和重构以此为准。
> 实现在 `scripts/core/battle_sim.gd`（结算）和 `scripts/core/card_db.gd`（装备合并、显示顺序）；战斗场景按 BattleSim 的事件日志回放。
> 标 **[待实现]** 的是已经决定、但现在还没实现的。

## 1. 术语与卡面文字

### 1.1 术语

| 术语 | 定义 |
|---|---|
| 战斗力 | 唯一数值，既是攻击也是生命 |
| 角色 | 战斗中的一张卡，可以带一件装备。卡面只用"角色"，文档里的"单位"同义 |
| 队列 | 一方的全部角色，从前往后排成一列，最多 7 个：己方队列 / 对方队列 |
| 位置 | 队列里从前往后数第几位；前面有人阵亡，后面的依次前移 |
| 交战位 | 第 1 位的专称；说"第 1 位""前两位"时都包含交战位。只有双方交战位互相攻击，存活的一方留在交战位，伤害不会恢复 |
| 下一位 | 紧挨在后面的己方角色；自己在最后一位时没有 |
| 全体 | 某一方队列里的所有角色，含自己 |
| 己方角色 / 己方其他角色 | 前者含自己，后者不含 |
| 己方 / 对方 | 相对卡牌的持有者，不用"我方""敌方" |
| 阵亡 | 判死时点战斗力 ≤0，被移出队列 |
| 战斗力 +N | 增益，不受坚固、庇护影响 |
| 受到 N 点伤害 | 走伤害流程（第 4 节）。统一写"对方……受到 N 点伤害"，不写"对对方造成 N 点伤害" |
| 触发 | 时机到了，角色的基础技能生效一次 |
| X值 | 技能后面的 N，如集结值、腐蚀值 |
| 基础技能 | 带数值，在时机触发（第 3 节） |
| 特殊技能 | 不带时机的是被动，在队列中（含战斗力 ≤0、还没判死的）就生效，被移出队列即失效；带时机的在该时间节点先于基础技能触发（第 2 节）。如地狱之主在队列中时，己方的振奋都按湮灭结算 |

- **时机**：
  - 战前：战前阶段按位置轮到时触发；
  - 入场：第一次成为交战位时触发；
  - 交战：每次交战前都触发；
  - 没有时机的技能不会主动触发，只作为被统计的数值（如大将军的集结5）。
- 卡面不说"在场"：被动效果默认只在己方队列中生效，不用写出来。
- 句子省略对象时指自身；需要强调时写"自身"。

### 1.2 显示顺序

代码里各只定义一处（`CardDB`），卡面、实时状态、图鉴共用；数据里怎么写都按这个顺序显示。

- **基础技能**就是结算顺序，作用对象由近及远、先加后减，局外收益最后：狂暴（自己）→ 集结（自己，汇总全队）→ 支援（下一位）→ 振奋（己方全体）→ 腐蚀（对方交战位）→ 湮灭（对方全体）→ 财富。
- **特殊技能**按所属种族，同族里基础特殊技能在前：反噬 → 坚固 → 队长的效果 → 唤醒 → 庇护 → 致命 → 蟾蜍的效果。
- **种族**：动物 → 人族 → 精灵 → 神族 → 自然（基础五族）→ 财宝。扩展种族的编号排在后面，它们的词条可以插在结算顺序中间。
- **时机**：战前 → 入场 → 交战。

### 1.3 分隔符

- 种族、时机、基础技能之间用"、"，如"动物、人族""战前、交战""狂暴2、集结1"。
- 特殊技能之间用"；"，如"坚固4；致命"。带时机的特殊技能写"时机：效果"，如"战前：唤醒；致命"。
- 分隔符在翻译表里（`ui.card.separator`、`ui.card.special_separator`）。
- 文字放不下时，卡面标签按字数自动缩小字号。
- 描述型的特殊技能（如"己方角色触发集结时，自身战斗力 +2"）不起词条名，卡面直接写整句。
- **飘字**：带数字的只表示战斗力变化（"狂暴 + 2""腐蚀 - 3"）。描述型特殊技能用来源卡的名字：改了战斗力的带数字（"队长 + 2"），没改战斗力的只弹名字（蟾蜍的腐蚀加成只弹"蟾蜍"）。来源是提供特殊技能那一格的卡，装备覆盖了特殊技能时就是装备。

## 2. 流程

### 2.1 时间节点

战前的每一步、入场、交战，都是一个**时间节点**。一个时间节点内从上到下结算（对应卡面上特殊技能栏在基础技能栏上面）：

0. **出列**：在这个时机触发的双方角色出列。
1. **第 1 轮**：
   1. **特殊技能**：带该时机的特殊技能，双方同时触发。获得庇护的最先结算（神佑）**[待实现]**，然后是其他的（现在只有唤醒）。
   2. **被唤醒的一组**：被唤醒的角色出列，结算它的基础技能。唤醒相当于插入一次触发，双方被唤醒的同时结算。
   3. **原本的一组**：双方原本在这个时机触发的角色结算基础技能。
2. **第 2 轮及以后**（有"多一轮"时，见第 3 节）**[待实现]**：多一轮的角色把 1.1–1.3 再走一遍。双方都有就一起走，只有一方就另一方等着。
3. 交战时点：所有轮结束后才对撞，然后结算协战 **[待实现]**、反噬。
4. 时点结束才判死、补位。**中途不判死**：时点里任何时候战斗力 ≤0 的单位都还在队列里，后面的效果照常作用于它，也照常统计它，它自己的效果也照常发动。唯一的例外是交战位战斗力 ≤0 时不对撞（2.2），之后的协战、反噬也不结算。

每一组基础技能都按**拍**结算，顺序见 1.2：

- 每一拍里，这一组双方的单位同时结算该技能；这一组都没有该技能的拍直接跳过；
- 同一拍里双方的效果互不影响：增益只作用于己方，伤害只作用于对方；
- "先加后减"只在同一组里保证；跨组以时间先后为准，可能先被扣成负数、再被加回来。这只影响画面，不影响结果（中途不判死）。

**顺序影响什么**：中途不判死，所以纯粹加减战斗力的效果，结果与先后无关。先后只影响：

- 庇护挡下哪一下、获得的庇护来不来得及挡（见第 4 节）；
- 以后才有的：中途获得的坚固、免疫，"变为""翻倍"这类非加减的效果，以及看当前状态的条件。

### 2.2 战斗流程

1. **战前阶段**：
   - 第 k 步取双方各自第 k 个存活单位，不论它有没有战前时机；
   - 在战前触发的单位（战前时机，或者带战前时机的特殊技能）按 2.1 结算；
   - 每一步之后判死，并判断是否一方全灭。战前阶段不判平局。
2. **主循环**：
   1. 判胜负和平局。
   2. 任一方交战位有还没触发的入场：按 2.1 结算双方交战位的入场技能，判死，回到第 1 步。
   3. 交战位有交战时机的单位按 2.1 结算。
   4. 双方交战位的战斗力都大于 0 时，互相攻击：双方同时受到等于对方战斗力的伤害（致命另算）。有一方 ≤0 就不对撞，视为没有发生对撞，第 5、6 步也跳过。
   5. 结算协战 **[待实现]**。
   6. 结算反噬。
   7. 判死、补位，回到第 1 步。

结果必须与座位无关：交换左右后结果对称，测试对每条用例都做镜像检查。

## 3. 基础技能

| 技能 | 说明 |
|---|---|
| 狂暴N | 自身战斗力 +N |
| 集结N | 自身战斗力 + 己方全体的集结值之和（没有时机的也算） |
| 支援N | 下一位角色战斗力 +N。自己在最后一位时不生效；每触发一次加一次 |
| 振奋N | 己方全体战斗力 +N |
| 腐蚀N | 对方交战位受到 N 点伤害 |
| 湮灭N | 对方全体各受到 N 点伤害。只出现在最高星级，目前没有卡 |
| 财富N | 获得 N 金币。现在只有特效（黄色数字），不产生金币，不影响胜负 **[金币待经济系统]** |

- 说明在翻译表里（`keyword_desc.<id>`，时机的说明是 `timing_desc.<id>`），图鉴点卡放大时列出。
- 被特殊技能**转化**来的技能（如振奋转湮灭），并入目标技能，在目标技能那一拍结算，数值和自带的合并。卡面上分开显示，用不同颜色区分。

### 3.1 多触发 **[待实现，等第一张需要的 3★ 卡]**

只有两种：

- **多一次**：某类技能（如腐蚀）或整组基础技能，在一轮里多结算一次。
  - 多出来的次数在同一拍里连续结算，每一下分开过庇护和坚固，各自算一次"触发"（会触发队长、蟾蜍这类效果）；
  - 特殊技能多一次：紧接在它自己（含唤醒带出的那一组）之后再来一次；
  - 多个"多一次"相加：腐蚀多一次加上基础技能多一次，腐蚀一共触发 3 次。
- **多一轮**：针对整个时点，把这一轮（特殊技能、被唤醒的一组、原本的一组，以及其中的"多一次"）完整再走一遍。和"多一次"相乘：上面的例子再加多一轮，腐蚀一共 3×2 = 6 次。被唤醒的那一组也会被重走。

## 4. 特殊技能与伤害

**伤害流程**：

1. 伤害大于 0 且有庇护：挡下这次伤害，消耗一层庇护，到此为止；
2. 否则减去坚固（以后的免疫和坚固在同一层），最低为 0；
3. 扣除战斗力。

**庇护**像套在外面的一层盾：任何大于 0 的伤害都会先打掉它，坚固本来能挡掉的伤害也一样。

| 词条 | 说明 |
|---|---|
| 反噬N | 每次交战后，自身受到 N 点伤害。只在实际发生交战后结算，双方都结算 |
| 坚固N | 每次受到的伤害 −N（最低为 0）。坚固随特殊技能整体替换，所以一个单位只有一个坚固值 |
| 庇护N | 抵挡 N 次伤害，每次消耗一层，先于坚固判定。战斗中获得的庇护叠加层数；装备合并仍是整格覆盖（圣骑士带圣盾还是庇护1） |
| 致命 | 交战时攻击视为无穷大（实现为 10000），可被庇护抵挡 |
| 唤醒 | 触发下一位角色的基础技能。带时机，写作"战前：唤醒" |
| 协战 | 己方其他角色交战时，对撞之后，对方交战位受到等于自身战斗力的伤害（人族）**[待实现]** |
| 神佑N | 下一位角色获得 N 层庇护。带时机，写作"战前：神佑2"（神族）**[待实现]** |

- **词条的数值降到 0 就移除**（如庇护用完），以后统计词条个数的效果也不算它。卡面上也不再显示 **[待实现：现在卡面还显示"庇护0"]**。

**协战** **[待实现]**：

- 在对撞之后、反噬之前结算；只在实际对撞后触发（交战位有一方 ≤0、没有对撞时不触发）。
- 持有者自己在交战位时不触发（"其他角色"）。
- 多个协战按位置从前往后扫描（和战前一样）：第 2 位、第 3 位……同一位置上双方都有就同时结算；每一下单独走伤害流程。
- 持有者战斗力 ≤0（还没判死）也照常触发，伤害等于它的战斗力；不大于 0 就是 0 点伤害，不消耗庇护。

**神佑** **[待实现]**：带时机的特殊技能，在该时间节点的特殊技能阶段最先结算，这一步获得的庇护可以挡这一步的伤害；下一位没有时不生效；层数叠加。

**唤醒**（带时机的特殊技能）：

- 时机属于特殊技能本身，和卡牌的时机无关：闪光球装在交战角色身上，也只在战前唤醒。
- 唤醒相当于插入一次触发：下一位角色的整组基础技能（包括装备给的）作为"被唤醒的一组"，在原本的角色之前结算（2.1）。
- 被唤醒的角色自己的时机照常触发；没有时机的角色也能被唤醒（如大将军的集结5）。
- 不连锁：只触发基础技能，不触发下一位自己的唤醒。
- 例：光灵在第 1 位，精灵虎在第 2 位。战前第 1 步光灵唤醒精灵虎，狂暴 +9；第 2 步精灵虎自己的战前时机再 +9，一共 +18。
- 例：树精带闪光球（战前腐蚀10、唤醒），后面是蟾蜍，对方是圣骑士（8，庇护1）。被唤醒的蟾蜍先出手，腐蚀 7 被庇护挡下；树精的腐蚀 12（蟾蜍也给它加 2）打中，圣骑士阵亡。

**条件触发的特殊技能**（描述型，卡面写整句）：持有者在队列中就生效；持有者自己触发也算；同名卡各自生效，效果叠加。

| 卡 | 效果 | 结算 |
|---|---|---|
| 队长 | 己方角色触发集结时，自身战斗力 +2 | 在集结拍，每有一个己方角色触发集结，队长 +2 |
| 蟾蜍 | 己方角色结算腐蚀时，伤害 +2 | 加在这一次的腐蚀值上再进伤害流程，卡面上的腐蚀值不变：腐蚀2 打坚固4 是 (2+2)−4 = 0 |

唤醒、以后的"多一次""多一轮"带来的触发，也会触发这两个效果。

- 腐蚀、湮灭、协战、反噬、致命都走伤害流程，每一下各消耗一层庇护。湮灭能一次打掉对方每个单位的一层庇护。
- 庇护挡哪一下，由 2.1 的结算顺序决定：先轮次，再组（被唤醒的在原本的之前），组内按拍（先腐蚀后湮灭）；交战时点最后是对撞、协战、反噬。
- **获得庇护优先** **[待实现]**：在特殊技能阶段最先结算，这一步获得的庇护可以挡这一步的伤害。
- **特殊技能的作用点**：
  - 装备合并时；
  - 指定时间节点（先于基础技能）；
  - 基础技能触发时（如多一次、多一轮）；
  - 基础技能结算时和伤害流程中（如腐蚀加成、免疫腐蚀）。
  - 局外的效果另行设计。
- **战斗中获得的词条**（以后才有）**叠加**到单位已有的词条上，不覆盖。整体替换只发生在装备合并时。

## 5. 死亡与胜负

- **判死时点**：只在固定时点统一判死，即每个战前步骤后、每次入场后、每次交战后。两个时点之间，战斗力 ≤0 的单位仍在队列里，会被集结统计。
- **移除**：判死时一次性移除全部阵亡单位。
- **胜负**：一方没有单位、另一方还有，则后者胜；双方同时没有单位，平局。
- **平局**：
  - 连续 20 次交战无人阵亡，判平局；
  - 有人阵亡（包括入场后判死）则计数清零；
  - 这条保证战斗必然结束。
  - 2026-11-02 用 20000 场随机对局验证：把上限放宽到 1000 次交战，被这条判平局的对局仍是平局；有人阵亡的对局里，阵亡前最长连续无人阵亡 4 次交战。
- 冒险、对战模式里平局怎么结算（比如比剩余战斗力），到设计局外规则时再定。

## 6. 装备叠加（格子模型）

装备像一张卡**盖在**角色卡上。卡牌有这几格，角色和装备都可以填任意格：

| 格子 | 数据字段 | 合并 |
|---|---|---|
| 战斗力 | `strength` | 不分格：角色的加上装备的，装备不覆盖角色的战斗力 |
| 时机-1 / -2 | `timing_1` / `timing_2` | 两格取并集；每个时机都触发全部基础技能 |
| 基础技能-1 / -2 | `skills_1` / `skills_2` | 两格同名数值相加 |
| 特殊技能 | `special_skills` | 只有一格，整体覆盖 |

先逐格处理，再把两格合并：

- 装备那一格是空的：沿用角色的；
- 有内容：覆盖角色的；
- 写着"空"（数据里是 `"clear"`）：把角色那一格清空。

通常角色填 1、装备填 2，效果就是叠加；装备填 1 就是覆盖角色那一格，比如空心的"基础技能-1：空"。

- 因为特殊技能整体覆盖，带特殊技能的装备会抹掉角色自带的特殊能力（如地狱之主带圣盾就不再转化）。想同时具备致命和庇护，只能角色自带两者、装备自带两者，或者以后在战斗中获得词条。
- 数据字段说明见 [data/README.md](../../data/README.md)。

## 7. 事件日志

`BattleSim` 结算时记录事件，战斗场景按事件播放，测试用它检查自洽。格式见 `scripts/core/battle_sim.gd` 开头的说明，主要有：

- `start`：双方初始阵容；
- `pre_battle`、`enter`、`engage`：每一步；
- `special`：特殊技能阶段（唤醒）；
- `beat`：一拍里双方的增益和伤害（财富只记数值，不改战斗力），带结算后的战斗力；被唤醒那一组的拍标 `woken`；
- `clash`、`backlash`：对撞和反噬；
- `death`：阵亡；
- `end`：胜负和原因。

日志带版本号 `BattleSim.VERSION`（现在是 3），规则或格式变化时加一，供以后的重播判断版本。
