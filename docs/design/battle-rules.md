# 战斗规则

> 活文档：战斗核心的规则规范，测试和重构以此为准。
> 实现在 `scripts/core/battle_sim.gd`（结算）和 `scripts/core/card_db.gd`（装备合并）；战斗场景按 BattleSim 的事件日志回放。
> 标 **[待实现]** 的是已经决定、但现在还没实现的。
> 接手时的三方对照（docx/规则表、Python、Godot）见 [../takeover/02-battle-rules.md](../takeover/02-battle-rules.md)。

## 1. 基本概念

- **战斗力**：唯一数值，既是攻击也是生命；≤0 即阵亡。
- **队列**：每方最多 7 个角色，第 1 位是交战位，只有交战位互相攻击。存活的一方留在交战位，伤害不会恢复。
- **在场**：在队列里就算在场，包括战力 ≤0、但还没到判死时点被移除的单位。
- **装备**：每个角色最多带 1 件。
- **时机**：
  - 战前；
  - 入场；
  - 交战：每次交战前都触发；
  - 出售：战斗内不触发。
  - 没有时机的技能不会主动触发，只作为被统计的数值（如大将军的集结5）。
- **普通技能**：带数值，在时机触发。
- **特殊技能**：
  - 没有时机的是被动，在场就生效。比如地狱之主在场时，己方的振奋都按湮灭结算；它离场后恢复。
  - 带时机的（以后才有）在该时间节点先于普通技能触发，见第 2 节。

## 2. 流程

### 2.1 时间节点与分拍

战前的每一步、入场、交战，都是一个**时间节点**。一个时间节点内按下面的顺序结算：

1. **特殊技能阶段**（以后才有）：
   - 带该时机的特殊技能，双方同时触发；
   - 需要的话，之后判死一次。被先手击杀的单位，其普通技能不再触发。这是有意的顺序博弈。
2. **普通技能阶段**：按技能分**拍**，顺序是 **狂暴 → 集结 → 振奋 → 腐蚀 → 湮灭**，先加后减。
   - 每一拍，双方所有在这个时机触发的单位同时结算该技能；
   - 双方都没有该技能的拍直接跳过；
   - 同一拍里双方的效果互不影响：增益只作用于己方，伤害只作用于对方。以后出现会互相影响的效果时，再定规则。

### 2.2 战斗流程

1. **战前阶段**：
   - 第 k 步取双方各自第 k 个存活单位，不论它有没有战前时机；
   - 有战前时机的单位按 2.1 结算；
   - 每一步之后判死，并判断是否一方全灭。战前阶段不判平局。
2. **主循环**：
   1. 判胜负和平局。
   2. 任一方交战位有还没触发的入场：按 2.1 结算双方交战位的入场技能，判死，回到第 1 步。
   3. 交战位有交战时机的单位按 2.1 结算。
   4. 双方交战位的战力都大于 0 时，同时对对方造成等于自身战力的伤害（致命另算）。
   5. 结算反噬。
   6. 判死、补位，回到第 1 步。

结果必须与座位无关：交换左右后结果对称，测试对每条用例都做镜像检查。

## 3. 普通技能

| 技能 | 效果 |
|---|---|
| 狂暴N | 自身 +N |
| 集结N | 自身加上己方当前队列所有单位的集结值之和（含自己，也含无时机的单位） |
| 振奋N | 己方全体（含自己）+N。这是加成，不是伤害 |
| 腐蚀N | 对方队列第 1 位受 N 点伤害 |
| 湮灭N | 对方队列从前到后，每个单位各受 N 点伤害。只出现在最高星级，目前没有卡 |
| 财富N | 获得 N 金币 **[等经济系统]** |

- 被特殊技能**转化**来的技能（如振奋转湮灭），并入目标技能，在目标技能那一拍结算，数值和自带的合并。卡面上分开显示，用不同颜色区分。
- "**再触发一次**"（如原精灵女王）指这个单位的整组普通技能再走一轮，不是数值 ×2。对伤害类技能，两者不同：每一下都会单独被坚固减免、被庇护抵挡。

## 4. 特殊技能与伤害

**伤害流程**：

1. 伤害减去坚固值，最低为 0；
2. 若伤害仍大于 0 且有未用的庇护：挡下这次伤害，消耗庇护；
3. 扣除战力。

| 词条 | 效果 |
|---|---|
| 坚固N | 每次受伤减 N。坚固是特殊技能，随特殊技能整体替换，所以一个单位只有一个坚固值 |
| 庇护 | 挡下一次大于 0 的伤害，在坚固之后判定 |
| 致命 | 交战时攻击值视为无穷大（实现为 10000），会被庇护挡下 |
| 反噬N | 实际发生交战后，自身受 N 点伤害，走伤害流程（坚固、庇护生效），双方都结算 |

- 腐蚀、湮灭、反噬都走伤害流程，所以都会被坚固减免，也都会消耗庇护。因此湮灭能一次打掉对方全体的庇护。
- 庇护挡哪一下，由普通技能的固定顺序决定：同一个时间节点里，先腐蚀，后湮灭。
- **特殊技能的作用点**：
  - 装备合并时；
  - 指定时间节点（先于普通技能）；
  - 普通技能触发时（如再触发一次）；
  - 普通技能结算时和伤害流程中（如腐蚀加成、免疫腐蚀）。
  - 局外的效果另行设计。
- **战斗中获得的词条**（以后才有）**叠加**到单位已有的词条上，不覆盖。整体替换只发生在装备合并时。

## 5. 死亡与胜负

- **判死时点**：只在固定时点统一判死，即每个战前步骤后、每次入场后、每次交战后。两个时点之间，战力 ≤0 的单位仍在队列里，会被集结统计。
- **移除**：判死时一次性移除全部阵亡单位。
- **胜负**：一方没有单位、另一方还有，则后者胜；双方同时没有单位，平局。
- **平局**：
  - 连续 20 次交战无人阵亡，判平局；
  - 有人阵亡（包括入场后判死）则计数清零；
  - 这条保证战斗必然结束。
  - 2026-11-02 用 20000 场随机对局验证：把上限放宽到 1000 次交战，被这条判平局的对局仍是平局；有人阵亡的对局里，阵亡前最长连续无人阵亡 4 次交战。
  - 曾经还有"连续 7 次检查全场战力不变"，已去掉；它在战前阶段也计数，导致 6 人以上、战前没有变化的对局一开打就判平局（B9）。
- 冒险、对战模式里平局怎么结算（比如比剩余战力），到设计局外规则时再定。

## 6. 装备叠加

装备像一张卡**盖在**角色卡上，逐格处理：

- 装备那一格是空的：沿用角色的；
- 有内容：覆盖角色的；
- 写着"空"（数据里是 `"clear"`）：把角色那一格清空。

| 格 | 语义 |
|---|---|
| 武器战力 | 加到角色战力上 |
| 武器时机 | 与角色时机取并集；每个时机都执行该角色的全部普通技能 |
| 武器技能 | 同名技能数值相加，否则追加 |
| 基础时机 | 覆盖角色时机；"空"即清空（目前没有装备使用） |
| 基础技能 | 整体覆盖角色的普通技能，空心即"空" |
| 特殊技能 | 整体覆盖角色的特殊技能；"空"即清空 |

- 武器格是叠加的，角色本身没有武器格，所以和叠放模型不冲突。
- 因为特殊技能整体覆盖，带特殊技能的装备会抹掉角色自带的特殊能力（如地狱之主带圣盾就不再转化）。想同时具备致命和庇护，只能角色自带两者、装备自带两者，或者以后在战斗中获得词条。

## 7. 事件日志

`BattleSim` 结算时记录事件，战斗场景按事件播放，测试用它检查自洽。格式见 `scripts/core/battle_sim.gd` 开头的说明，主要有：

- `start`：双方初始阵容；
- `pre_battle`、`enter`、`engage`：每一步；
- `beat`：一拍里双方的增益和伤害，带结算后的战力；
- `clash`、`backlash`：对撞和反噬；
- `death`：阵亡；
- `end`：胜负和原因。

日志带版本号 `BattleSim.VERSION`，规则或格式变化时加一，供以后的重播判断版本。
