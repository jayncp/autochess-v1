# 战斗规则

> 活文档：战斗核心的规则规范，测试和重构以此为准。
> 标 **[待实现]** 的是已经决定、但 Godot 现在还不是这样的。
> 接手时的三方对照（docx/规则表、Python、Godot）见 [../takeover/02-battle-rules.md](../takeover/02-battle-rules.md)。

## 1. 基本概念

- **战斗力**：唯一数值，既是攻击也是生命；≤0 即阵亡。
- **队列**：每方最多 7 个角色，第 1 位是交战位，只有交战位互相攻击。存活的一方留在交战位，伤害不会恢复。
- **装备**：每个角色最多带 1 件。
- **时机**：
  - 战前；
  - 入场；
  - 交战：每次交战前都触发；
  - 出售：战斗内不触发。
  - 没有时机的技能不会主动触发，只作为被统计的数值（如大将军的集结5）。
- **普通技能**带数值、在时机触发；**特殊技能**是常驻被动。

## 2. 流程

1. **战前阶段**：
   - 第 k 步取双方各自第 k 个存活单位，不论它有没有战前时机；
   - 有战前时机的单位执行普通技能，P1 先、P2 后；
   - 每一步之后判死。
2. **主循环**：
   1. 判胜负和平局。
   2. 任一方交战位有还没触发的入场：双方各自执行入场技能（P1 先），判死，回到第 1 步。
   3. 交战位有交战时机的单位执行普通技能（P1 先）。
   4. 双方交战位的战力都大于 0 时，同时对对方造成等于自身战力的伤害（致命另算）。
   5. 结算反噬。
   6. 判死、补位，回到第 1 步。

"P1 先、P2 后"只是执行顺序，结果必须与座位无关：交换左右后结果对称 **[待实现：反噬有短路 bug，会让结果随座位变化]**。

## 3. 普通技能

触发时按固定顺序结算：**狂暴 → 集结 → 腐蚀 → 振奋 → 湮灭**。

| 技能 | 效果 |
|---|---|
| 狂暴N | 自身 +N |
| 集结N | 自身加上己方当前队列所有单位的集结值之和（含自己，也含无时机的单位） |
| 腐蚀N | 对方队列第 1 位受 N 点伤害 |
| 振奋N | 己方全体（含自己）+N。这是加成，不是伤害 |
| 湮灭N | 对方每个单位各受 N 点伤害 **[待实现]**。只出现在最高星级 |
| 财富N | 获得 N 金币 **[等经济系统]** |

## 4. 特殊技能与伤害

**伤害流程**：

1. 伤害减去所有坚固之和，最低为 0；
2. 若伤害仍大于 0 且有未用的庇护：挡下这次伤害，消耗庇护；
3. 扣除战力。

| 词条 | 效果 |
|---|---|
| 坚固N | 每次受伤减 N；多个坚固求和 **[待实现：目前只取最后一个]** |
| 庇护 | 挡下一次大于 0 的伤害，在坚固之后判定 |
| 致命 | 交战时攻击值视为无穷大（实现为 10000），会被庇护挡下 |
| 反噬N | 实际发生交战后，自身受 N 点伤害，走伤害流程（坚固、庇护生效），双方都结算 **[待实现：目前直接扣战力，且有短路 bug]** |

腐蚀、湮灭、反噬都走伤害流程，所以都会被坚固减免，也都会消耗庇护。因此湮灭能一次打掉对方全体的庇护。

## 5. 死亡与胜负

- **判死时点**：只在固定时点统一判死，即每个战前步骤后、每次入场后、每次交战后。两个时点之间，战力 ≤0 的单位仍在队列里，还能吃到振奋，也会被集结统计。
- **移除**：判死时一次性移除全部阵亡单位 **[待实现：目前相邻两个同时阵亡时会漏删一个]**。
- **胜负**：一方没有单位、另一方还有，则后者胜；双方同时没有单位，平局。
- **平局**：满足任一条即判平局 **[待实现第二条]**：
  - 连续 7 次检查，双方全场战力都不变；
  - 连续 20 轮无人阵亡。
  - 两条合起来保证战斗必然结束。

## 6. 装备叠加

| 装备字段 | 语义 |
|---|---|
| 武器战力 | 加到角色战力上 |
| 武器时机 | 与角色时机取并集；每个时机都执行该角色的全部普通技能 |
| 武器技能 | 同名技能数值相加，否则追加 |
| 基础时机 | 整体替换角色时机（目前没有装备使用） |
| 基础技能 | 整体替换角色的普通技能，空心即清空 **[待实现：目前按技能名逐个覆盖]** |
| 特殊技能 | 整体替换角色的特殊技能 |
