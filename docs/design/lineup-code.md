# 阵容码

> 活文档：阵容码的写法、导入的规则和界面。计划和执行记录见 [../plans/lineup-code.md](../plans/lineup-code.md)，用例在 `tests/cases/lineup_codes.json`。

阵容码把**一方**的阵容写成一段可以复制、粘贴、手改的文字，用来导出和导入：

```
鹦鹉+狮心 / 士兵 / 士兵 / 千机魔女+铁剑
```

只有文字这一种形式，不带数据版本：阵容码只说是哪些卡，不保证强度。导入时只和当前版本的卡核对，认得出的位置导入，认不出的位置空着并说明；玩家调整后再导出就是新的。

## 1. 写法

一方从交战位往后最多 7 个位置，每个位置是一个角色加可选的一件装备。

**导出**只有一种写法：

- 位置之间是 ` / `（两边各一个空格）；
- 有装备的写 `角色+装备`，中间没有空格；
- 卡名用当前语言的名字；
- 空着的卡位跳过不写（开战时本来就自动往前补）。

**导入**放宽，因为文字会经过聊天软件、输入法和手改：

- 分隔符两边的空格、制表符忽略；全角空格、不换行空格当成普通空格。
- 全角的 `＋` `／` 当成半角。
- 换行也当作位置分隔，可以一行写一个位置：
  - 换行和它旁边的 `/` 合起来算一个分隔（`老虎 /⏎士兵`、`老虎⏎/ 士兵` 都是两个位置）；
  - 空行不算位置，首尾的空白和空行都忽略。
- 卡名要完全匹配，认现在的卡名和英文 id；不做模糊匹配。
- 卡名内部的空格不动（中文名没有空格，以后英文名会有）。

卡名里不能有 `+`、`/` 和它们的全角写法；卡名之间不能重复，也不能和别的卡的英文 id 相同。测试的数据检查保证这几条。

搜索报告里的阵容就是这个写法（`牛头人+天使翅膀 / 光灵 / 沼泽之王+噬心药剂`），可以直接贴进游戏。

## 2. 导入的规则

按位置一个一个看，互不影响：

- 第 k 段文字对应第 k 个卡位。
- 角色认得出：放上去。装备认得出就带上，认不出就不带装备。
- 角色认不出（写错了、卡已经删了或改名了、写的是一件装备）：这个卡位空着。
- 一段是空的（`老虎 / / 士兵`，或者一行只写了一个 `/`）：这个卡位空着，不算问题。
- 写了不止一件装备：只带第一件。
- 超过 7 段：只取前 7 段。
- 一个角色都认不出：不导入，原来的阵容不动。

有问题的地方逐条说明：

| 情况 | 卡位 | 说明 |
|---|---|---|
| 角色认不出 | 空着 | 第 2 位：不认识"士宾" |
| 角色的位置写了装备 | 空着 | 第 1 位："狮心"不是角色 |
| 只有装备（`+狮心`） | 空着 | 第 1 位：没有角色 |
| 装备认不出 | 角色不带装备 | 第 1 位：不认识装备"师心" |
| 装备的位置写了角色 | 角色不带装备 | 第 1 位："士兵"不是装备 |
| 不止一件装备 | 只带第一件 | 第 1 位：只能带一件装备，没有带上"铁剑" |
| 超过 7 段 | 只取前 7 段 | 最多 7 个位置，后 2 个没有导入 |
| 一个角色都认不出 | 不导入 | 没有可以导入的角色（下面再列出不认识的名字） |

加人、改人之后：加了新卡，以前的文字都不变，新卡直接用名字；调了数值或技能，照常导入，按现在的数值算；卡改了名或删掉了，那个位置空着；图鉴里换了顺序、英文 id 改了，用卡名写的不受影响；换了游戏语言，用英文 id 写的照常导入，用另一种语言的卡名写的认不出。

## 3. 界面

科研模式右列"清空全部"下面的"阵容码"按钮，双方共用一个面板（`LineupCodePanel`，`scenes/components/ui/lineup_code_panel.gd`；外框同对话框）：

- 顶部切换对方、我方（单选块，字前面一面小旗，红、蓝同阵营旗帜）；打开时是当前选中的卡位所在的一方。
- 一个文本框：里面是这一方现在的阵容（标准写法），可以直接复制；也可以改或者贴上别的再导入。这一方没有角色时是空的，带一句提示"在这里粘贴或输入阵容，如：老虎+狮心 / 士兵"。
- "复制"：复制文本框里的内容，按钮上的字变成"已复制"1.5 秒。
- "粘贴"：剪贴板的内容换掉文本框里的；读不到剪贴板（有的手机和网页版）时提示在文本框里直接粘贴。
- "导入"：
  - 一个角色都认不出：文本框下面提示"没有可以导入的角色"，阵容不变；
  - 这一方已有角色时先确认"将替换我方当前的阵容"；
  - 导入后文本框换成导入后的阵容（标准写法）；有要说明的就列在文本框下面，没有就关掉面板。
- 点框外关闭。

面板带一个"能不能导入"的开关：不能导入时文本框只读，只有"复制"。现在只挂在科研模式；关卡布阵页以后只开导出。

## 4. 实现

- `scripts/core/lineup_code.gd`（`LineupCode`）：纯逻辑，不依赖场景。`write(阵容)` 得到文字；`read(文字)` 得到 7 个卡位和问题的列表。阵容的格式和 `BattleSim` 一样是 `[[角色 id, 装备 id], ...]`，空卡位是 `[]`。问题是结构化的（第几位、哪一种、哪个名字），文字由界面用翻译拼（`ui.lineup_code.*`）。
- 测试：`tests/cases/lineup_codes.json` 的用例逐条核对（"加人、改人之后"的用例临时改卡牌数据或翻译）；全部卡各写一次再读回来；数据检查卡名不重复、不含分隔符；冒烟流程在科研模式里走一遍导出、清空、导入、确认、带问题的导入。
