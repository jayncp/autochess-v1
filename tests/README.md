# 测试

## 运行

| 命令 | 作用 |
|---|---|
| `just test` | 全部测试，约 2 秒：数据检查、战斗用例、单元测试、回放检查、冒烟流程。运行中出现任何错误都算失败 |
| `just record` | 用当前引擎重录战斗用例的期望值，并列出结果变化的用例 |
| `just gen-random` | 重新生成随机用例（固定种子），之后运行 `just record` |
| `just levels` | 枚举两个关卡的全部摆法，打印解，并把解写入 level 组，之后运行 `just record` |

- Godot 路径默认是 `/Applications/Godot.app/Contents/MacOS/Godot`，可以用环境变量 `GODOT` 覆盖。
- CI（`.github/workflows/test.yml`）在推送到 main 和提交 PR 时运行 `just test`。
## 测试项（`run_tests.gd`）

| 测试 | 内容 |
|---|---|
| 数据检查 | 卡牌、种族、时机、词条、关卡都有中文名，词条都有说明（在英文环境下检查，确认能回退到中文）；列出还在用占位图的卡，不算失败。数据字段和 id 的合法性由 `CardDB`、`LevelDB` 加载时校验 |
| 战斗用例 | 直接调 `BattleSim`：结果符合期望；交换左右后对称；事件日志自洽（按效果推演的战力、判死和最终结果都对得上） |
| 单元测试 | 对战用例触发不到的情况：相邻两个单位同时阵亡、湮灭、格子模型；新机制（支援、财富、唤醒、队长和蟾蜍的效果）在有正式卡之前用测试专用卡（`TEST_CARDS`）测，跑完回放检查后移除；卡面文字 |
| 回放检查 | 战斗场景最后显示的胜负和战力与 `BattleSim` 一致：动画播完、僵持压缩、中途跳过、新机制 |
| 冒烟流程 | 从主菜单走一遍科研模式、两个关卡、图鉴，全程不报错；其中的战斗也做回放检查。第一关还会按 `docs/design/game-design.md` 第 7 节逐条检查布阵交互：直接调用拖放逻辑，不经过鼠标 |

## 战斗用例 `golden/battles.jsonl`

一行一条：`id`、`group`、双方阵容 `p1`/`p2`（`[[角色 id, 装备 id], ...]`，装备为空字符串表示不带）、期望结果 `expect`（胜负 1/2/3 = P1 胜 / P2 胜 / 平局，以及双方幸存单位的战力）、可选的 `note`。

| 分组 | 内容 | 维护方式 |
|---|---|---|
| rule | 每条规则一条，期望值手算 | 规则改变时手动改期望值和备注 |
| docx | 战斗流程文档的例子 | 一般不变 |
| design | 体现设计意图的对局（如 1★ 循环克制） | 设计意图变化时调整 |
| level | 关卡的全部解 | `just levels` 重新生成 |
| random | 固定种子的随机对局 | 卡牌增删后 `just gen-random` |

`"asymmetric": true` 表示已知交换左右结果不同（规则 bug 造成，修复后去掉），镜像检查会跳过它们。目前没有这样的用例。

## 维护原则

- **改了规则、数据或卡牌**：运行 `just record`，逐条核对结果变化的用例都在预期范围内，再和改动一起提交。
- **保持精简、有代表性**：一条规则一条用例；新增用例前先看现有用例是否已经覆盖；删掉被别的用例完全覆盖的冗余用例。
- **只有对战用例触发不到的情况**才写单元测试。
